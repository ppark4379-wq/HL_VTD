# M16 체크포인트 및 검증 상태

사진의 PathShape01 좌표 8개를 `checkpoints.csv`에 소수점 셋째 자리까지
그대로 반영했습니다. VTD 저장본의 PathShape 좌표와도 일치합니다.
원본 XML을 패키지로 복사했으며 원본 장면이나 Ego 위치는 수정하지 않았습니다.

- 체크포인트 구조: 시작 1, 진입·진출 2→3 / 4→5 / 6→7, 도착 8.
- 미션 연결: `hl_vtd --check-config` 검사에서 4개 주행 구간과
  3개 교차로 생성 및 C++ 로딩 통과. 그림은 `mission_corridor.svg`입니다.
- 차선 중심 경로 CSV 생성: road 2641 / lane -1 / index 828에서
  곡률 0.291260 1/m로 0.200 제한을 초과해 실패했습니다.
  lane-snap 방식도 index 212의 road_s 역진행 검사에 실패했습니다.
- `checkpoint_shape.csv`와 `checkpoint_shape.svg`는 체크포인트를 직선으로
  연결한 형상 확인용 자료입니다. 주행용 `route.csv`로 사용하지 않습니다.

검사를 우회하거나 허용치를 완화하지 않았으며, 유효한 `route.csv`가 없어
`run_scenario.py`의 전체 사전 검사는 아직 통과하지 못했습니다.
현재 원본 Ego는 (377.530, -258.977)에 있어 새 시작 좌표
(1381.092, -192.225)와도 다릅니다. 실행하려면 경로 생성 문제 해결과
원본 Ego의 시작 위치/방향 설정이 필요합니다. 실제 VTD 주행은 하지 않았습니다.
