# M17 경로 안정화와 M18 코너 이탈 분석 (2026-09-10)

## 범위

사용자 요청: M18은 원인 분석만, M17은 재현 후 공통 로직을 개선하고 M09
밀집 장애물에서도 확인. 신호/보행자 대기·동적 비상제동·게이트웨이 통과
조건을 유지한다. 이번에는 실선 검사 강화, 속도/제동/조향 설정을 수정하지 않았다.
이전 중앙 비용·상시 중앙 복귀 재계획은 이미 롤백되어 있던 상태에서 시작했다.

## M17: 확인된 원인과 변경

### 원인

1. 차가 경로를 심하게 못 따라간 것이 아니라, 선택 경로 자체가 점선 근처에
   오래 놓여 있었다. 수정 전 추종 오차 중앙값 1.08cm, 95백분위 9.43cm.
2. 기존 로컬 탐색은 중앙과 차선 내 오프셋을 한꺼번에 거리/곡률 비용으로
   비교했다. 안전한 중앙 경로가 있어도 더 작은 횡이동으로 점선에 걸치는
   후보가 선택될 수 있었다.
3. 54m 이상을 만드는 경로 연장 탐색이 잔여 50m에서 다시 활성화됐다.
   안전한 복귀 경로를 끝까지 따라가기 전에 새로운 경로로 바꿀 수 있는 구조였다.
   수정 전 실제 로컬 경로 채택 13회. 12.277초 채택 후 12.836초 다시 채택했고,
   같은 차량 위치에서 비교한 10m 앞 경로가 약 1.13m 반대로 바뀌었다.
4. 모든 방향 변경이 불필요한 것은 아니다. 수정 후에도 0.880/0.919초는
   객체 20/21(자전거), 104.116/105.519초 부근은 객체 26의 동적 위험 때문에
   `active_path_became_unsafe`로 새 경로를 찾았다. 이 안전 반응은 유지했다.

### 변경

- `searchLocalCorridor`: 차선 중앙 상태만 쓰는 완전한 회피·복귀 후보를 먼저
  검사한다. 실패하면 종전 5개 횡방향 상태로 탐색한다. 중앙 전용 탐색은
  별도 강제 비용이나 전역 도로 선택 변경이 아니다. 커브/차선변경 곡선은
  당연히 중앙 밖을 지날 수 있으며, 정착 지점을 중앙으로 찾는 의미다.
- 중앙 탐색도 종전과 동일한 충돌·차체·노면·곡률·게이트웨이/복귀 확인을
  통과해야 한다. 중앙 해가 없다고 정지하거나 밀집 회피 후보를 없애지 않는다.
- 중앙 탐색은 그래프 준비 후 남은 예산의 1/4, 최대 8ms. 기존 비동기 worker
  시간 예산 안에서 수행하며 그래프/edge 검사 캐시는 전체 샘플 탐색에 재사용한다.
- 안전한 현재 로컬 경로의 연장 기준을 `max(20m, 속도×5초+8m)`로 분리했다.
  5km/h에서는 20m, 15km/h에서는 약 28.8m. 장애물 활성화 50m는 그대로다.
  새 위험·현재 경로 충돌 검사는 이 연장 기준과 무관하게 매 프레임 실행한다.
- 별도 최소 접촉 복구, 게이트웨이/코리더 복귀, 제한적 복귀 노면,
  전역 비용, 신호·보행자·동적 비상제동은 변경하지 않았다.
- 중앙 선호만으로 현재 경로를 교체하는 상시 재계획은 추가하지 않았다.

## M18: 경로가 없어서 처음부터 못 돈 것은 아님

분석 실행: `output/verification/M18/m18_corner_diag_20260910`.
기존 코드로 재현 후 장시간 정지 상태를 확인하고 약 145.7초에 실행을 종료했다.
평균 제어 루프 약 20.00Hz, 처리 시간 95백분위 약 30.95ms.
이 코너 실패를 제어 주파수 저하로 설명할 근거는 없었다.

### 실제 순서

| 시점 | 기록 |
|---|---|
| 약 68.8초 | 420:-1에서 의도한 연결 도로 797:-1로 진입 |
| 약 69초 | 추종 경로 49점이 존재. 이 시점 시각화 경로 최대 점 간격 약 1.0m |
| 69.99초 | 요구 조향 -0.636rad, 송신은 한계 -0.48rad |
| 70.99초 | 요구 -0.933rad, 송신 -0.48rad. 차선 중앙 오차 약 0.637m |
| 약 71.4초 | 경로 오차 1m 초과로 lookahead가 3m에서 6m 이상으로 증가 |
| 71.99초 | 중앙 오차 약 1.47m, lookahead 약 6.94m |
| 약 73초 | 도로 매칭을 잃고 기존 멀어진 경로를 유지. lookahead 약 9.14m |
| 75.792초 | 한 프레임 사이 약 2.43m 위치 변화와 2.455rad 방향 변화; 794로 매칭 |
| 이후 | 81.592/88.231초에도 약 2.4m 위치 불연속. 결국 반대 방향 420:+1 쪽으로 이동 |
| 92.711초 이후 | `active_path_input_invalid`, `plan_valid=0`, 제어 입력 보호 제동으로 정지 |

원본 사용자가 남긴 M18 기록에서도 같은 코너 이탈/정지 위치가 확인된다.

### 사전 경로 문제인가, 제어 문제인가?

- 지도 사전 샘플의 797:-1 최대 곡률은 약 0.155/m, 반경 약 6.45m다.
  화면상 완만해 보여도 실제 선택된 안쪽 연결 차선은 급하다. 경로가
  통째로 누락되었거나 이 지점에서 좌표가 크게 끊어진 증거는 없다.
- 생성기는 최대 곡률 약 0.17685/m를 사용한다. 하지만 실제 VTD 주행에서
  69.8~72.4초의 이동량 약 6.08m/방향 변화 약 0.394rad는 평균 반경 약
  15.4m에 해당한다. 계획의 기하학적 가능 판정만으로 실제 추종 가능성이
  보장되지 않고 있다. 조향 명령 단위/차량 모델 응답/지연의 구체적 원인은
  추가 계측이 필요하며, 이 값만으로 통신 단위 오류라고 단정하지 않는다.
- `path_planner.cpp`는 오차가 1m를 넘으면 `clamp(4+2×오차,6,14)`까지
  앞을 더 멀리 바라본다. 멀어진 직선 경로로 부드럽게 복귀하려는 설정이
  이 작은 반경의 코너에서는 회전 끝 너머를 겨냥하며 보정 조향을 줄인다.
  최초 이탈은 이 조건 이전에 시작되며, 이 조건은 이후 악화 요인이다.
- 따라서 **급한 지도 경로와 실차 모델의 추종 가능성 검증 부족 + 조향 포화 +
  급코너에 맞지 않는 오차 복귀 lookahead**가 확인된 문제다. 단순히 중앙
  비용을 더 주거나 경로를 다시 만들기만 해서 해결할 유형이 아니다.

### RViz에서 전역 경로가 안 보인 이유

`global_route`는 현재 시각화에서 전체 좌표가 아닌 메타데이터만 보낸다.
파란 선은 실제 추종용 `localPath.points`다. M18 저장 전역 경로는 693점,
`reaches_gateway=true` 상태로 남아 있었지만 새 경로 탐색은 실패한 상태였다.
정지 때도 오래된 추종용 점들은 남아 있으나 차량이 거기서 떨어져 있어 유효한
실행 경로로 선택할 수 없었다. 즉 화면에서 전역 선이 안 보이는 것과
처음부터 전역 경로를 한 번도 만들지 못한 것은 다른 문제다.

### 왜 복귀하지 못하고 정지했나?

- 도로 매칭 자체가 사라진 동안에는 `prepareLocalCorridorFallback`의
  `egoLaneValid` 진입 조건 때문에 확장 복귀 탐색에 들어가지 못한다.
- 반대 방향 차선에 다시 매칭된 뒤에는 복귀 worker를 반복 실행했지만
  `tracking_recovery_exhausted corridor_tested=0`, tier 2 실패가 반복됐다.
  가까운 정상 경로가 있더라도 현재 방향에서 전진 곡선으로 연결 가능한
  유효 후보가 없었다. 가까운 길을 고르는 것과 물리적으로 연결하는 것은 다르다.
- `stored_precomputed_path_forced`로 기존 경로를 남겨도 활성 경로 선택은 실패한다.
  최종 `planning.valid = tracking.valid && world.inputValid`가 거짓이므로
  명목 목표속도 1.5m/s만 설정해도 최종 입력 보호 제동을 넘을 수 없다.
- 2.4m 위치 점프는 현재 20m 기준의 `respawnDetected`에는 잡히지 않는다.
  이것이 VTD 재배치인지 인터페이스 측 현상인지는 이 로그만으로 확정할 수 없다.
  Ego 시나리오에는 이 구간의 위치 재설정 액션이 없고 수신 좌표는 그대로 사용된다.

### 다음 수정 우선순위 제안 — 이번에는 미적용

1. 고정 조향/저속 시험이나 RDB 계측으로 VTD 조향 명령 대비 실제 곡률을
   확인하고 경로 곡률·속도 가능 판정을 그 모델에 맞춘다. 무조건 조향 상한을
   늘리는 방식은 사용하지 않는다.
2. 급코너에서는 오차가 커졌다는 이유만으로 lookahead를 6~14m로 키우지
   않도록 곡률·조향 여유를 반영한다. 코너 진입 전 감속/조향 예측과 연속적인
   복귀를 함께 시험한다. 직선/고속/밀집 회피의 기존 추종도 회귀 검증한다.
3. 방향을 잃기 전에, 유효한 차량 위치와 실제 주행 노면을 근거로 복귀를
   시작할 수 있게 지도 매칭과 복귀 허가를 분리한다. 게이트웨이 통과,
   차체·동적 위험·물리적으로 가능한 연결 검사는 유지한다.
4. 이미 반대 방향으로 크게 돌아간 상황은 별도 기동이 필요한 한계 상황이다.
   유효하지 않은 경로에 가속만 강제하거나 가장 가까운 도로를 즉시 추종하는
   것으로 복귀를 보장할 수 없다.

## 테스트와 남은 제한

- 집중 CTest 7개 통과: 최소 접촉 후보 선택, 제한적 복귀, 길을 잃었을 때 복귀,
  불필요한 중앙 재계획 없음, 조기/밀집/오래된 결과/게이트웨이 로컬 탐색,
  밀집 저속, 안전한 회피 후반부 인계.
- 별도 기존 안전 회귀 12개 통과 (`controller_logic_tests --preserved-safety`).
- 2.20m 틈을 두 단계로 통과하는 로컬 테스트 10회 반복 통과. 일반 .30m
  여유로는 안 되고 .05m 여유/full offsets가 필요한 장면이다.
- 기존 `--m09-dense-obstacle-replay` 통과.
- 기존 `--m09-compact-obstacle-replay`는 실패한다. 이번 중앙 탐색 변경을
  제거한 별도 `/tmp/corridor_lattice_stability_baseline_tests`로도 같은
  `M09 compact avoidance physically intersects an object` 실패와 동일 선택
  경로를 확인했다. 현재 실주행 M09와 신규 비동기 밀집 검사는 통과하지만,
  기존 단일 C2 선택기의 별도 결함까지 고친 상태는 아니다.
- 모든 시나리오에서 무충돌/완주를 보장한다는 의미가 아니다. 전역 중앙 비용,
  신호/보행자 대기, 동적 비상제동, 실선 검사 강화는 이번에 수정하지 않았다.
