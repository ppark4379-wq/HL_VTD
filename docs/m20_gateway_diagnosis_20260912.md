# 게이트웨이 대기·복귀 실패 분석과 수정

## 확인한 실행

원본은 `output/verification/M20/m20_rviz/run.csv`와 해당 실행의 `rviz/latest.json`이다. 조사 시점 스냅샷과 비교 입력·결과는 `output/tmp/m20_gateway_diagnosis_20260912/`에 보존했다.

- 약 20~35초: 진입도로 126의 4차선에서 정지선에 접근했다. 필요한 게이트웨이는 5차선에서 이어지는 `1094:-1`이다.
- 약 40초 이후 직진하여 2426의 -2차선으로 들어갔다. 약 50초부터 `plan_valid=0`이고 정지했다.
- 보존한 실제 스냅샷의 전역 경로는 0점이다. 작업자는 155점 경로를 만들었지만 실제 차량과 경로의 시작부가 약 2.85m 떨어져 `successful_route_not_adopted`로 반복 폐기했다.
- 초기 구간의 전체 판단 이벤트 이력은 저장되어 있지 않다. 따라서 최초 대기 경로가 정확히 어느 프레임에서 탈락했는지는 단정하지 않는다. 아래 재구성 검사는 CSV의 자세·정지 차량 관측과 스냅샷의 고정 장애물을 사용하며 실제 폐루프 주행과 구분한다.

## 원인

1. 대기 판정이 `soleGatewayApproachPath` 생성·채택에 의존했다. 전역 작업자가 탐색 중이거나 경로를 채택하지 못하면 실제 진입 차선에 정지 차량이 있어도 대기 보호가 없었다. 옆 차선에서는 장애물과의 횡방향 겹침 조건도 해제됐다.
2. `forwardPath()`가 게이트웨이 도달 가능한 직진 간선을 찾지 못하면 도달성을 요구하지 않는 직진 간선으로 재시도했다. 허용 콜리더에 속해 있어도 이후 차선 변경 공간이 없어지는 지점까지 진행할 수 있었다. 짧은 접근 경로 끝은 미션 도착점이 아니므로 기존 도착 정지 처리만으로 이를 막지 못했다.
3. 전역 작업자가 지도 샘플에서 경로를 시작하여 실제 자세와 연결되지 않는 성공 결과를 반복 생성했다. 복귀 탐색은 전방 투영 6m 이상·작은 방향 차이 위주여서 옆의 회전 게이트웨이 후보를 놓쳤다.
4. 복귀 작업자가 같은 잘못된 진입 차선의 짧은 경로를 최저 비용으로 선택하고, 채택 단계에서는 최소 잔여 길이 부족으로 거절하는 반복도 재현했다. 실제 게이트웨이 복귀 후보가 이 결과에 가려졌다.

`generateLocalPath()`는 선택 경로의 전방 구간을 잘라 주는 함수다. 전역 탐색·대기 접근·복귀 탐색·기본 추종 경로가 `corridor_lattice.cpp`에 함께 있다. RViz의 짧은 추종선만으로 어떤 탐색이 성공했는지 판별할 수 없다. 이번에는 대기 경로 점 수, 대기 선택 여부, 복귀 선택 여부를 시각화 JSON에도 추가했다.

## 변경

- 차체 폭·곡률·주행면·장애물을 반영한 게이트웨이 연결 전역 경로를 먼저 탐색한다. 유효한 전체 경로가 있으면 사용하고, 없으면 실제로 막힌 직접 진입 차선의 장애물 뒤까지 접근 경로를 탐색한다.
- 우회/대기 선택에서 정지선·체크포인트와의 거리 제한을 제거했다. 탐색 중이거나 예외가 발생한 상태는 통과 경로가 없다는 결론으로 취급하지 않는다. 완료된 탐색의 장애물 정보를 별도로 보관하므로 대기 접근 경로의 채택 실패나 옆 차선 이동으로 그 판단을 잃지 않는다.
- 게이트웨이 도달성을 잃는 직진 간선을 기본 추종에 쓰지 않는다. 접근 경로의 끝에는 감속 상한을 적용하고, 그 지점에 도달하기 전에 복귀 탐색을 시작한다.
- 전역 작업자에서 실제 자세와 연결되는 곡선을 검사하고, 연결 후에도 필수 게이트웨이 통과를 재검사한다.
- 제한된 복귀 탐색에서는 측방 회전 후보와 출발 차선 주변의 실제 지도 차선 면을 검사한다. 복귀 끝점은 추가 횡이동 없이 게이트웨이에 이어지는 차선이어야 하고, 채택에 필요한 잔여 길이도 탐색 단계에서 확인한다.
- 진행 복구 타임아웃도 필수 게이트웨이에 연결되지 않는 직진 탈출을 허용하지 않는다.

시나리오 번호·특정 좌표·차량 ID 분기는 추가하지 않았다. 장애물 충돌 검사, 차체 주행면 검사, 실선 검사와 설정된 0.50m 장애물 여유는 유지한다.

## 검증

관련 CTest 14개 통과: 직접 대기 검출, 게이트웨이 변경 마감, 단일/복수 대기, 개방 우회 우선, 콜리더 이탈 복귀, 경로 인계·유지, 횡단보도 등.

| 비교 입력 | 확인한 출력 |
|---|---|
| 약 10초 자세 + 원래 정지 차량 | `126:4 → 126:5` 대기 접근, 156점, 무충돌, 전역 게이트웨이 완료로 오인하지 않음 |
| 같은 입력에서 정지 차량을 진행방향 기준 25m 상류로 이동 | `126:4 → 126:5 → 1094:-1 → 1043` 전역 우회, 389점, 무충돌. 대기 선택 없음 |
| 약 25초의 옆 차선 자세에서 정지 차량이 떠난 비교 입력 | `126:4 → 126:5 → 1094:-1` 복귀, 107점, 실제 자세 연결·무충돌·복귀 선택 확인 |

위의 두 비교 입력 변경은 진단용 JSON에만 적용했다. 시나리오나 NPC 설정을 바꾸지 않았다. 고정 관측 재검증이며 새 VTD 폐루프 주행·미션 완주 인증은 아니다.

25m는 위 비교 입력을 만든 이동량일 뿐 정책의 임계값이 아니다. 추가 회귀검사는 장애물과 게이트웨이 위치를 동일하게 두고 합법적 차선 변경 가능 여부만 바꾼다. 전체 통과 경로가 있으면 우회하고, 없으면 정지선 거리와 관계없이 실제 진입 차선 장애물 뒤에 대기하는지를 검사한다.

이미 직진 연결도로 안쪽까지 진입한 실제 정지 위치 `(729.096, -265.806)`에서는 검사한 전진 복귀 곡선이 지도 주행면 경계에 걸려 승인되지 않았다. 이 위치의 복귀 성공은 확인하지 못했다. 수정의 검증된 효과는 진입 전 대기/우회 구분, 옆 차선에서의 게이트웨이 복귀, 복귀 가능 지점을 지나 직진하는 행동 차단이다. 실행 중 프로세스에는 새 실행파일이 자동 반영되지 않는다.
