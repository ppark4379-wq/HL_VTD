# M17 빈 도로 차로 왕복·복귀 편향 수정 (2026-09-10)

## 관측과 원인

- 기존 `m17_stability_repeat_20260910`에서 64.052초에 1→2차로,
  79.053초에 2→1차로 이동했다. 66.732초 연장 탐색 시 받은 객체 세 개는
  모두 뒤에 있었다. 앞 객체의 과거 좌표가 남은 것이 아니라, 19.132초에
  만든 경로의 끝 차로와 연장 탐색이 다시 고른 끝 차로가 달랐다.
- 객체 수신·WorldState·정적 확정 이력은 현재 관측으로 갱신된다. 해당 장면을
  유령 객체로 설명할 근거는 없었다. 실제 동적 위험으로 경로가 바뀐 다른
  장면까지 불필요한 회피라고 분류하지 않는다.
- 84~94초 선택 경로가 차로 중앙보다 진행 방향 오른쪽으로 약 0.41m 치우쳤다.
  이는 `차로 반폭 1.5 − 차폭 반폭 0.94 − 여유 0.15 = 0.41m` 오프셋 슬롯이다.
  실제 추종 오차는 그 구간 약 1~5cm였다. 원본 XODR 중앙점이 밀린 것이 아니다.
- 84.97초 계획 차체의 실선 여유가 약 6mm였고 실제 차체는 약 5.6cm 넘어갔다.
  옆으로 치우친 복귀 곡선과 작은 자세 추종 오차가 함께 여유를 소진했다.
  바퀴 접촉/공식 VTD 감점 센서가 아닌 XODR와 차체 OBB 분석이다.
- 별도로 단일 장애물 회피 준비 상태에서, 같은 객체 ID가 계속 보이면
  그 객체가 경로를 비켜도 회피 준비를 유지할 수 있었다.

## 공통 코드 변경

1. 로컬 후보의 후반부에서는 장애물 묶음을 차체 뒤까지 지난 뒤 중앙에 정착하고
   불필요한 같은 도로 내 차로 이동을 하지 않는 후보를 우선한다. 게이트웨이
   연결에 필요한 차로 이동은 허용한다. 새로운 전역 중앙 비용은 추가하지 않았다.
2. 우선 후보가 실패하면 기존 전체 횡방향 샘플로 돌아간다. 밀집 장애물,
   차체·노면·충돌·게이트웨이 검사와 제한적 코리더 복귀는 유지한다.
   추가 탐색도 기존 worker 시간 예산 안에서 수행한다.
3. 앞 장애물 없이 기존 로컬 경로의 길이만 연장할 때는, 이미 검증한 복귀선을
   먼저 보존하고 실제 종점의 종방향 연결 도로를 연장한다. 현재 객체 전체를
   다시 검사한다. 연장 구간이 막히거나 게이트웨이 권한/노면/현재 자세 연결
   조건에 맞지 않으면 기존 A* 탐색으로 넘어간다. 제어 스레드에서 탐색하지 않는다.
4. 12m 우선 정착 조건에는 그래프와 같은 0.75m 샘플 허용오차를 적용한다.
   1차 재실행에서 실제 12m 간선은 12.0383m였고, 6/8m 복귀 곡선은 곡률
   제한을 넘었는데 12.0383m의 유효 후보가 3.8cm 초과로 탈락하는 문제를 찾았다.
5. 단일 장애물 회피 **준비 중에만**, 원인 객체가 원래 경로를 비켰고
   안전한 후속 경로가 현재 자세와 0.2m/0.15rad 이내로 연결되면 취소한다.
   실행 중 회피·다단계 회피·게이트웨이 이동을 무조건 취소하지 않는다.

도로 밖 보행자가 존재한다는 사실만으로 새 회피를 강제하는 규칙은 추가하지
않았다. 실제 진입·충돌 예측, 신호·횡단보도 대기, 동적 비상제동은 변경하지 않았다.
속도·LD·조향 한계도 이번 수정에서 변경하지 않았다.

## 검증

- 1차 `m17_clear_tail_20260910`: 171.30초 도착, 경로 무효 0, 기록상 객체 충돌 0.
  road173 차로 전환은 기존 7→5회이며, 문제의 빈 도로 2→1→2 왕복은 사라졌다.
  다만 0.41m 편향이 남아 샘플 허용오차와 기존 복귀선 보존을 추가했다.
  이 1차 기록을 최종 수정 후 결과로 해석하면 안 된다.
- 기본 안전 12개, 준비 중 회피 취소 검사, 로컬 밀집 2단계 2.20m 틈 검사,
  코리더 재진입/경로 상실 복귀/불필요 재계획 억제, M09 밀집 재생,
  M15 정확한 게이트웨이·잘못된 평행 분기 방지 검사를 수행했다.
- 복귀선 보존 후 `m17_clear_tail_final_20260910`: 132.44초 도착, 경로 무효 0,
  기록상 객체 충돌 및 기록된 OBB 접촉 0, 실제 명령 송신 평균 19.951Hz.
  같은 물리적 구간 road173 S=70~100m에서 차로 이동 0회, 선택 경로 중앙 편차
  최대 7.3mm/p95 6.0mm, 실제 추종 오차 p95 3.6mm였다.
  더 넓은 S=50~130m에서도 같은 현재 자세에서 전방 3/6/10m 경로를 비교한
  15cm 초과 교체는 0회였다. road173 전체 차로 전환은 기존 7→3회.
- 위 실행 뒤 연장 경로의 차체·코리더 전 구간 재검사와 0.75m/0.25rad
  현재 자세 연결 사전 검사를 명시했다. 모두 포함한 최신 빌드에서
  전체 로컬 테스트, 집중 CTest 7개, 준비 취소 검사, 안전 부분집합 12개 통과.
  `m17_clear_tail_guarded_20260910`으로 최종 안전 보완까지 재실행했다.
- 안전 검사 포함 버전의 같은 road173 S=70~100m에서 차로 이동 0회,
  선택 경로 중앙 편차 최대 5.6mm/p95 4.0mm, 실제 추종 오차 p95 3.7mm.
  계획/실제 차체와 실선의 최소 여유는 각각 54.4/55.5cm였다.
  S=50~130m에서도 전방 3/6/10m 경로의 15cm 초과 교체는 0회였다.
  road173 전체 차로 이동은 3회이며, 초기 객체 회피와 이후 보행자 구간이다.
  최종 169.29초에 설정된 시작점(0-based leg 2)부터 목표까지 도착했다.
  경로 무효 0, 기록상 충돌 및 기록된 객체 OBB 접촉 0이다.
  실제 명령 송신 평균 19.863Hz, 송신 간격 p95 85.44ms,
  planning 처리시간 p95 36.24ms였다. 종료 후 자동 실행기가 VTD Stop을 보냈다.

신규 회귀 테스트는 비정수 0.5016m 지도 샘플의 12.0384m 복귀,
기존 20m 복귀선 좌표 보존 및 종방향 연장, 기존 경로 종점 이후 새 장애물
발견 시 연장 거절/안전 회피 대안, 지나간 객체와 도로 밖 객체의 불필요 회피 방지를
포함한다. 이 통과 결과는 모든 시나리오의 무충돌이나 공식 채점 완주 보장이 아니다.

## 별도 확인된 VTD 차량 제원 문제

[차량 제원 혼용 독립 재현](vtd_vehicle_definition_diagnosis_20260910.md)을 참고한다.
설치된 `viTrafficDyn`의 `default=true` 설정에서 NPC VehicleDef가 Ego 모델에
적용되는 것을 재현했다. 이번 M17 실행은 외부 VTD 설정을 바꾸지 않았으므로
그 문제의 수정 후 실주행 검증이 아니다. 명시적 Ego 바인딩을 적용하고 새 INIT한
뒤에는 추종과 회피를 다시 검증해야 한다.
