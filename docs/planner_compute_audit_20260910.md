# 계산 최적화와 속도·감속 설정 점검 (2026-09-10)

이번 변경은 계산 최적화만 적용했다. `config/control.yaml`의 속도·감속,
신호·보행자·동적 EBS, 후보 순서/비용/탐색 단계/시간 예산은 바꾸지 않았다.

## 로그에서 확인한 주기와 속도

최신 파일 `output/verification/M17/m17_rviz/run.csv` (09:37 수정),
4,638프레임, 기록 구간 242.80초:

- 프레임 기록 기준 평균 19.10Hz, 마지막 500개 간격은 20.00Hz.
- 전체 간격 중앙값 40.27ms, p95 84.90ms, 최대 124.97ms.
- 목표속도 5km/h인 프레임은 3,488개(약 75.2%).
- 최신 실행에는 `timing.csv`가 없어 정확한 송신 간격 및 최신 단계별
  계산시간은 알 수 없다. 위 수치는 `elapsed_wall_time_s` 차분이며
  실시간으로 현재 실행 중인 프로세스를 측정한 값도 아니다.

이전 08:42 진단 실행의 `timing.csv`에는 전송 평균 17.42Hz,
planning 평균 22.24ms / p95 70.32ms, world 평균 11.39ms,
visualization 평균 0.41ms가 기록되어 있다. 이전 실행의 수치이므로
현재 CPU 병목이나 RViz 렉 원인을 이 수치만으로 확정할 수 없다.

앞선 기능 변경으로 확장 로컬 worker의 예산은 80ms에서 최대 240ms가 됐고,
접촉 복구 재평가도 추가됐다. 비동기 작업이어도 CPU 사용은 증가할 수 있다.
반면 목표속도 5km/h는 처리속도가 아니라 로컬 fallback/tight tail의 명시적
속도 상한이기도 하므로 계산량 감소만으로 해당 상한이 올라가지는 않는다.

## 적용한 최적화

`corridor_surface_query.hpp`의 검사 단위 임시 캐시로, 같은 공간 셀의
허용 도로 샘플/접선/차폭을 반복 조회하지 않는다. 차체 전체 주행면 검사,
확장 탐색의 중간 차체 검사, 복귀 증명에 사용한다.

- 기존 9개 셀 순서와 각 셀 내부 순서, 거리·방향·차폭 판정식,
  동점에서 선택하는 도로 샘플 ID를 그대로 보존한다.
- 차체/경로 검사 샘플을 줄이거나 위험 검사를 건너뛰지 않는다.
- 동일 자세의 sin/cos를 차체 샘플마다 다시 계산하지 않는다.
- 캐시는 단일 검사/불변 탐색 관측 안에서만 사용하며 프레임 또는 미션
  변경 이후로 가져가지 않는다. 새 도로 권한을 이전 캐시로 검사하지 않는다.

기존 함수를 독립적으로 보존한 비교 테스트에서 61,440개 질의 결과가 일치했다.
순차 차체형 질의 24,000회의 비교 실행에서 약 10.90ms → 4.67ms였다.
이는 해당 연산의 합성 벤치마크이며 전체 제어 루프의 속도 향상률이 아니다.
벽시계 예산을 그대로 두었으므로 더 빨라진 검사로 시간 내 확인하는 후보가
늘어나거나 최종 선택이 달라질 수는 있다. 판단 기준이 바뀐 것은 아니다.

M17 저장 관측 95.2614초의 재생에서도 로컬 경로 생성 성공, 426점,
0.30m 충돌 검사 여유 통과, 올바른 781:-1 복귀를 확인했다.
실제 VTD 주행이나 최적화 후 송신 Hz는 측정하지 않았다.

전체 타깃 빌드 및 관련 CTest 11개(코리더 검사/차폭/전역 장애물/
로컬 fallback/복귀 캐시/복구 선택/속도 및 안전 인계) 통과.
전체 테스트 스위트가 아니라 이번 변경에 관련된 부분을 실행했다.

## 당시 승인 전 제안 (이후 적용 내역은 아래 절)

- 기본 직진/완만한 곡선 목표를 20km/h로 맞추고, 보호구역 목표도 그보다
  높지 않게 맞춘다. 현재 일반 설정은 직진 45 / 곡선 30km/h다.
- 일반 회피·주의는 15km/h 상한을 검토한다. 다만 현재
  `local_fallback_speed_kph` 하나가 여유 있는 회피와 5cm 간격의 tight tail을
  함께 제한한다. 이 값을 단순히 5→15로 올리면 좁은 회피까지 빨라진다.
  여유 있는 회피와 좁은/급한 회피의 상한 분리가 필요하다.
- 곡률 기반 감속, 적색신호/보행자 정지, EBS, 충돌 감수 탈출 저속은 유지한다.
  횡단보도/횡단 차량 대기 주의는 현재 10km/h다. 이 부분의 15km/h 상향은
  일반 회피와 별개로 출발 트리거·제동 여유 검증이 필요하다.
- `limits.min_acceleration=-4`는 EBS에서 즉시 보내는 가속도 하한이다.
  안전 제한기가 일반 가속도 변화율 제한 뒤에서 덮어쓰므로 -8로 바꾸면
  명령은 즉시 -8이지만, 실제 감속이 -8인지는 VTD 차량 응답으로 확인해야 한다.
  일반 PD 제동/정지 유지/입력 오류 제동의 하한도 함께 바뀐다.
  우선 -6으로 실제 응답을 측정하고 -8을 판단하는 단계적 튜닝을 제안한다.
- `planning.emergency_braking_deceleration=4`는 출력 하한과 달리 위험 문턱
  계산에 쓰인다. 이를 함께 8로 올리면 더 강한 제동을 가정해 문턱이
  달라질 수 있으므로 자동으로 같은 값으로 바꾸지 않는다.

## 사용자 승인 후 속도 정책 적용

후속 승인으로 속도 정책만 적용했다. 앞 절의 계산 최적화와 구분한다.

- `speed.straight_target_kph`: 45 → 20.
- `speed.curve_target_kph`: 30 → 20. 기존 곡률/조향 기반 물리 상한은 유지.
- `speed.school_zone_target_kph`: 25 → 20.
- `lane_change.maximum_lane_change_speed_kph`: 20 → 15.
- `planning.stationary_adjacent_vehicle_caution_kph`: 20 → 15.
  `nearby_object_caution_kph`는 이미 15이므로 유지.
- 새 `planning.local_fallback_open_speed_kph=15`: nominal 0.30m 여유로
  검증되고, 15km/h에서 곡률 기반 횡가속도가 기존 1.5m/s² 이하인 로컬
  회피에만 적용한다. 전방 곡률은 추종기와 같은 최근접점/25m 범위를 쓴다.
- 기존 `local_fallback_speed_kph=5`: nominal보다 좁은 경로(예: 0.05m),
  여유 미확인 경로, 위 횡가속도 한계를 넘는 급회피에 계속 적용한다.
  이 설정에서 급회피 경계는 곡률 약 0.0864/m(반경 약 11.6m)이다.
  좁은 경로는 회피 상태가 끝나도 그 경로를 추종하는 동안 저속을 유지한다.
- 기존 설정 파일에 새 키가 없으면 기존 fallback 속도를 그대로 상속한다.
- 후보 동적 충돌 예측 속도도 새 속도 정책에 맞췄다. 현재 실제 속도가
  상한보다 높으면 높은 실제 속도를 반영한다. worker는 nominal 후보의
  가능한 상한을 검사하고, 제어 스레드에서 현재 관측/곡률로 다시 검사한다.
- 모든 값은 상한이다. 신호·보행자 정지, 비상제동, 선행차/곡률/조향 제약으로
  더 낮거나 0인 목표를 올리지 않는다. 밀집 정적 구간 10, 횡단보도 위험 접근
  10, 급커브 설정 6, 접촉 복구 3km/h는 유지했다.
- `limits.min_acceleration=-4`, `emergency_braking_deceleration=4` 및
  신호·보행자 대기/비상제동 조건은 바꾸지 않았다.

설정/속도 분리 테스트는 20/15/5 설정, 급회피 경계, 불명확한 여유의 저속,
기존 설정 호환, 잘못된 새 값 거절, 기존 제동/위험 접근 설정 보존을 검사한다.
