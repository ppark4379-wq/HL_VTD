# M17 복귀·회피·장기 정지 진단 (2026-09-10)

주행 로직과 설정은 변경하지 않았다. 진단 실행과 정적 장면 분리 실험만 수행했다.

## 근거와 재현 범위

- 원본: `output/verification/M17/m17_rviz/run.csv`, 마지막 `rviz/latest.json`.
- 신규 실행: `output/verification/M17/m17_gateway_diag_20260910_0835_retry/`.
  `--auto-vtd --inline-scenario --skip-source-sync --evidence --run-timeout 190`.
  190초 제한으로 종료하고 VTD Stop을 보냈다. 원본은 최종 goal_reached=1이지만
  신규 실행은 그보다 앞의 정적 객체 2에서 막혀 완주하지 못했다. 사진 장면의 동일 재현은 아니다.
- 원본 115.181958초 Ego를 CSV에서 복원하고 원본 마지막 프레임의 정적 객체 2/3/4를
  사용한 고정 관측 전역 플래너 실험: 신규 실행 폴더의 `reconstructed_115/decision.log`.
  원본의 전체 관측·플래너 내부 상태를 복원한 것은 아니다.

## 확인 사항

1. 마지막 미션 구간 허용 차선에는 174:-1, 174:-2, 781:-1이 있지만 207은 없다.
   XODR상 207은 465로, 781은 190으로 이어지는 서로 다른 교차로 연결 도로다.
   화면상 중첩/인접 공간을 같은 경로 권한으로 취급하지 않는다.
2. 원본 115.18초 Ego는 207:-1이고 정식 경로와 약 2.89m 떨어져 있다.
   고정 관측 실험에서는 781에서 목표까지 135점 경로 생성에 성공했으나
   `successful_route_not_adopted attachment=2.89465 suffix_clear=1`로 거절된다.
   현재 채택 한계는 1.25m다. 경로 자체의 부재와 Ego 접속 경로의 부재는 다르다.
3. `recoverTrackingPath`는 공식 코리더 안에서만 접속 곡선을 검사한다.
   공식 코리더 밖에 있는 출발 차체도 검사하므로 복귀가 구조적으로 거절될 수 있다.
   고정 실험에서도 `tracking_recovery_exhausted outside_corridor_fallback=blocked`가 반복됐다.
4. 코리더만 풀면 충분한지도 별도 검사했다. 기존 `connectToReferencePath`를 재사용한
   임시 진단기(`/tmp/m17_bridge_probe.cpp`)로 원본 109.06/112.06/115.18초 위치에서
   781 중심선으로 접속을 시도했다. 초기 곡률은 통제 변수로 0을 사용했다.
   정적 객체 2/3/4가 모두 있으면 코리더 검사를 물리적 주행면 검사로 바꿔도 실패했다.
   객체 3만 제외하면 성공했고 객체 2 또는 4만 제외하면 실패했다.
   즉 현재 단일 접속 곡선+중심선 뒤쪽 경로 후보군에서는 트럭 3 충돌도 독립적인 제약이다.
   이 실험은 모든 무충돌 경로의 존재/부재를 증명하지 않는다.
5. 원본 114~124초 최근접/목표 경로 인덱스가 모두 1로 유지되고, 이후 lookahead가
   14m로 커지며 목표속도는 1.5m/s다. 약 119초부터 접촉 플래그와 실제 정지가 발생한다.
   교체 불가능한 저장 경로를 강제 추종하는 코드와 일치하는 증상이며,
   원본 decision.log가 없으므로 그 분기 실행 자체까지 확정하지는 않는다.
6. 신규 실행의 전역 탐색에는 `precomputed_gateway_unreachable`, 로컬에는
   `footprint_outside_corridor`, `offset_not_recentered`, `curvature_or_heading`,
   `collision`이 관측된다. 로컬 worker는 수 ms~수십 ms에 `timeout=0`으로도 실패한다.
   시간 예산 부족만으로 설명되지 않는다.
7. 신규 실행 114.102초 복구는 `checked=4`, 이후 선택들은 `checked=3`이다.
   복구 함수는 호출마다 bestCost를 초기화하고 15ms 안에 본 후보만 비교한다.
   선택 후 경로 이탈/꼬리 부족/0.5m 진행 없는 3초 정체가 아니면 재탐색하지 않는다.
   따라서 접촉하면서 조금씩 움직이면 나쁜 경로가 오래 유지될 수 있다.
   현재 비용은 차체 OBB 겹침의 대리 지표이지 VTD 실제 충돌 감점의 예측값이 아니다.
8. 신규 실행에서 신호 요청은 123.153초, 159.153초 활성 복구를 취소했다.
   정지선이 각각 약 16.2m, 7.9m 남아 있었고, 정적 장애물 속도 제한도 겹친다.
   `stop.valid` 하나로 복구 경로와 타이머까지 초기화하는 것이 문제를 증폭시킨다.
   정지 구간은 약 124.43~144.11초, 160.11~180.11초이고 신호 해제 뒤 다시
   복구 타이머를 기다린다. 타이머는 RDB 시뮬레이션 시간 기준이며 wall 시간과 다르다.
9. 신규 실행 전체 전송 평균은 17.42Hz, planning p95=70.39ms,
   송신 간격 p95=92.52ms, 최대 177.08ms다. 진단 로깅을 켠 측정이며
   20Hz 여유가 충분하다고 볼 수 없지만 수십 초 정지의 직접 원인은 아니다.

## 진단 당시 권장 수정 순서 (아래 수정 후 검증 참고)

1. 복귀 탐색의 출발 주행면과 최종 경로 권한을 분리한다. 현재의 실제 차체가 있는
   물리적 도로에서 출발하는 짧고 제한된 복귀 구간만 허용하고, 끝은 현재 미션의
   올바른 분기/게이트웨이 경로에 위치·방향·곡률이 연속되게 접속시킨다.
   실선, 보도, 반대 방향 차선, 동적 위험 제한은 유지한다.
   207 전체를 미션 경로로 승인하거나 1.25m 채택 한계를 키워 직접 추종하면 안 된다.
2. 단일 중심선 복귀뿐 아니라 회피→유지→복귀를 한 후보로 검사한다.
   비동기 전역 경로가 생성됐지만 떨어져 있는 경우에도 버리기 전에 Ego 접속을 탐색한다.
   코리더 끝/후속 경로 미승인/남은 추종 길이를 복귀 조기 탐색의 트리거로 삼는다.
3. 복구 후보를 좌우·짧은/중간/긴 길이별로 균등하게 먼저 평가하고, 프레임 간에
   탐색 진행을 보존한다. 선택된 접촉 경로도 주기적으로 현재 관측에서 재평가한다.
   무접촉 후보 우선, 접촉이 불가피한 경우 최대 겹침·누적 접촉·탈출 가능성 등으로
   순위를 정하되 동일한 평가 거리/시간을 사용한다. 전진량만으로 탈출 성공을 판단하지 않는다.
4. 신호·보행자 정지 명령과 동적 EBS는 유지하되, 정적 장애물 회피 계획 준비와
   정체 이력을 별도 상태로 보관한다. 해제 후 타이머를 매번 처음부터 반복하지 않도록 한다.
   정지선 이전 제한된 이동까지 허용할지는 별도 정책 결정이며 무단 적용하지 않는다.
5. 짧은 후보는 추가 선택지이지 만능 해결책이 아니다. 같은 횡이동량에서 길이를
   줄이면 곡률/조향 요구가 커지고 회전반경은 작아진다. 기존에도 6/8/10m 후보가 있다.
   권한·복귀 끝점·차체 통과·후속 경로를 먼저 해결해야 한다.

최소 회귀 확인 항목: 코리더 밖 출발 후 올바른 목표 복귀, 잘못된 분기 진입 방지,
분기 전 조기 복귀, 장기 접촉 경로 재평가, 신호/횡단보도 정지 유지,
동적 급끼어들기 EBS 유지, 정적 전환 후 복구, 20Hz 시간 예산.

위 내용은 수정 전 원인 분석이며, 이후 구현 내용은
`docs/local_corridor_fallback.md`의 ‘M17 진단 이후’ 절에 기록했다.

연결 후보를 만든다. 엄격 단계에서는 원래 주행면 검사를 유지하고,
제한 확장 단계에서만 추가 주행면을 사용할 수 있다.

  228점 로컬 경로 생성, 충돌 검사 여유 0.30m 통과.
  끝은 올바른 781:-1의 roadS=42.8281m로, 목표 단면 33.3661m보다
  약 9.46m 뒤다. 목표 단면 통과 검사도 통과했다.

- 두 장면 모두 전역 탐색 실패와 별개로 로컬 탐색은 성공했다.
  재시도 대기를 포함한 벽시계 시간은 각각 약 1.16초, 1.60초다.
  로컬 결과 확인 호출의 최대 시간은 각각 약 1.17ms, 1.47ms지만,

  `--preserved-safety` 12개를 통과했다. 전체 테스트 스위트를 실행한 것은 아니다.

109초 복원은 당시 전체 관측 이력의 정확한 재생이 아니라 정적 장면 실험이다.
두 결과 모두 저장된 관측에서의 경로 생성/검사 성공이며, 실제 조향 추종,
움직이는 객체의 이후 행동, 사진 시점에서의 탈출 또는 수정 후 M17 완주를
입증하지 않는다. 수정 후 실제 VTD 주행은 별도 검증해야 한다.
