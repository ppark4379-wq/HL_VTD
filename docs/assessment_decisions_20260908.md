# 2026-09-08 확정 기준 및 보호구역 반영 결과

보호구역 최신 검토 결과는 **43개 적용 / 15·28번 보류**다. 아래 35개/10개 기록은 수정 전 이력이며 [연결 보완 결과](living_lab_school_zone_review.md)가 우선한다.

이 문서 이후의 최신 결정(제어값 수신 시작, **마지막 체크포인트 도달 종료**)은 [최종 자동채점 기준](HL_VTD_자동채점_최종평가기준.md)을 따른다. 아래 과거 GOAL 반경 2m 설명이나 중간 결정인 정지선 후륜축 종료는 현재 기본 설정에 적용되지 않는다. 현재 도달 허용거리는 기존 제어기 `goal_tolerance`와 맞춘 **사용자 확정 1.5m**다.

이 문서는 같은 날 이전에 작성된 `dashboard_auto_assessment.md`의 변경 전 설명보다 우선한다.

## 적용한 기준

- 차로 유지: 사용자의 결정으로 평가에서 제외. 표시 항목은 14개이며 기존 번호를 유지한다.
- 총점: 사용자의 결정으로 500점부터 차감. 미평가 항목이 있으면 결과는 부분 평가다.
- 실선 차로변경: 같은 도로에서 실제 Lane ID가 변경되고 OBB 이동 구간이 실선을 통과한 경우에만 위반. 차선 접촉만으로는 감점하지 않는다. 기존 문서에 따라 구간 첫 위반 3점, 두 번째부터 구간 합계 6점.
- 리스폰: VTD가 자동 또는 운영자 조작으로 수행한다. 웹은 리스폰 명령을 전송하지 않는다. 이탈 직전 평가 구간에 귀속하여 첫 회 무료, 두 번째부터 매회 6점 누적 차감한다. 1초는 운영 측의 복구 설명이며 감점 타이머가 아니다. 수동 복구가 늦어져도 동일한 횟수 규칙이다.
- 리스폰 검출: 현재는 연속 수신 프레임에서 속도로 설명되지 않는 5m 초과 위치 재배치를 관측한다. 5m는 임시 검출 설정이며 공식 감점 기준도, VTD의 최소 이동거리 보장도 아니다. 작은 재배치·통신 공백 중 재배치·프레임/시간 초기화를 동반하는 재배치는 추가 확인이 필요하다. 프레임/시간 역행은 현재 새 세션 Reset으로 처리한다.
- 적색점멸: 0.5초 이상 완전 정지 후 통과 시 정지선 전방 2m 미만 정상, 2m 이상 경미 3점. 정지 없이 통과하면 중대 6점. 정지 판정 속도는 정확히 0km/h.
- 녹색 미출발: 예정 경로 전방 30m 이내 차량 진행 폭과 앞차·보행자·장애물 OBB가 겹치면 출발 방해 사유로 인정한다. 막힌 정지는 감점하지 않고, 사유 해소 후 타이머를 다시 시작한다.
- 보행자: 횡단보도 점유는 보행자 OBB가 완전히 빠져나갈 때까지 유지한다. 신호·횡단보도 위치 및 객체 수신 완전성 설정이 있어야 이 판정을 사용할 수 있다.

## 보호구역 자료 검증

원본: `tools/dashboard/living_lab_school_zones.yaml` 및 `living_lab_school_zones_summary.csv`.
45개 기록의 도로·차로가 모두 현재 OpenDRIVE에 존재한다. 기록 좌표를 도로에 투영한 S 오차는 최대 약 0.00584m다. 이 수치는 파일 내부 좌표 일치도이며 실제 적색 포장 경계의 측량 정확도를 보증하지 않는다.

35개 기록을 적용했다: 같은 도로·차로의 직접 범위 25개, OpenDRIVE의 유일한 연속 차로 연결로 확장한 기록 10개. 확장 결과 총 57개 도로·차로 S 범위가 생성된다. Lane ID가 도로 중간에서 바뀌는 경우에도 laneSection의 successor/predecessor 연결을 따른다. 단순히 두 S의 최솟값과 최댓값을 다른 도로에 적용하지 않는다.

보류 기록:

| 기록 번호 | 보류 사유 |
|---|---|
| 12, 15, 27, 28, 29, 39, 40, 42, 44 | 제공된 두 경계를 잇는 국소적인 단일 차로 연결을 확정할 수 없음. 경계 쌍 또는 중간 도로·차로 확인 필요 |
| 45 | 두 번째 경계 없음 |

보류 기록을 임의의 정상 구역으로 처리하지 않는다. 검증된 보호구역 내부는 30km/h 기준으로 감점할 수 있지만, 목록 밖 위치는 자료가 불완전하므로 보호구역 여부 미확정으로 남긴다. API의 `school_zone_validation`에 반영·보류 목록과 사유를 제공하며 전체 결과를 부분 평가로 표시한다.

판정 기준점은 후륜축이다. 첨부 HLVTD Ioniq 6 설정의 길이 4.848m, 폭 1.886m, 후륜축부터 전방 범퍼까지 3.808m와 RDB OBB 오프셋으로 후륜축 위치를 계산한다. 치수가 맞지 않는 차량에는 자동으로 이 보정을 적용하지 않는다. 다른 차량은 검증된 `metadata.rear_axle_offset_m`이 필요하다.

## 경로 및 남은 실차 연동 확인

현재 기본 경로 파일은 첨부 LivingLab Path01의 도로 128/S166.168부터 도로 1928/S84.842까지 생성한 차로 중심 경로다. 경로 진행률로 5등분하며 누적 주행거리로 구간을 바꾸지 않는다. 경로에서 멀리 벗어나 투영하지 못하면 마지막 구간을 유지한다.

생성 경로는 VTD PathRef 목표값보다 약 0.229m 짧다. 현재 생성 경로의 끝을 목표점으로 사용하며 GOAL 도달 반경은 사용자 확정값 1.5m다. 다른 경로의 시나리오에서는 해당 경로 CSV와 시작·목표를 설정해야 한다. 현재 RDB로 실행 XML을 자동 식별하는 기능은 없다.

실제 VTD에서 리스폰 검출, 신호/정지선 매칭, 횡단보도 영역과 객체 수신 완전성, 후륜축 보정, 영상 연결은 종단 간 확인이 남아 있다. 보호구역 파일 반영만으로 모든 항목이 현장에서 검증 완료된 것은 아니다.
