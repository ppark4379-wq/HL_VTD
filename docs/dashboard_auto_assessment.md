# HL VTD 자동채점 기준·구현·인수 점검

이 문서는 변경 이력이다. 현재 시작·종료·점수·구간·입력 상태는 [최종 기준](HL_VTD_자동채점_최종평가기준.md)을 따른다. 특히 최신 종료 조건은 **마지막 체크포인트 도달**이며, 별도 종료 정지선 확정은 필요 없다. 보호구역도 최신 검토 후 **43개 적용 / 15·28번 보류**로 변경되었으며 아래 35개/10개 설명은 수정 전 이력이다.

작성: 2026-09-08. 이 문서는 `HL 평가기준.docx`, 사용자가 전달한 주최 측 질의응답, 참고 영상 `KakaoTalk_20260904_144252189.mp4`를 기준으로 작성했다. 영상은 화면 동작 참고 자료이며, 영상에서 보이는 점수를 이용해 판정 임계값을 추정하지 않았다.

## 1. 현재 결론

**자동채점 엔진, VTD 읽기 전용 상태 수신, 실시간 대시보드, 영상 중계를 구현했다.** 현재는 차로 유지 제외로 14개 항목이며 초기 500점, 보호구역 35개를 반영했다. 보호구역 10개 경계 확인과 신호·횡단보도 연결, 실제 VTD 종단 간 시험이 남아 있다. [최신 기준 및 검증 결과](assessment_decisions_20260908.md)를 먼저 확인한다.

- VTD와 대시보드: 같은 Linux PC. 별도 제어기 PC의 로그/CSV를 기다리지 않는다.
- RDB 상태 출력에 읽기 전용 TCP 연결한다. 제어 명령을 송신하지 않으며 참가자 제어 포트 9910에는 연결하지 않는다.
- 기존 CSV 이력 조회는 유지한다. 기본 화면은 `VTD 실시간` 모드다.
- 점수·중대위반·현재구간·속도·거리·시간·잔여시간을 약 0.5초 간격으로 갱신한다. 영상 목표 출력은 10fps다. 실제 지연/프레임률은 VTD PC에서 측정해야 한다.
- 모르는 항목은 `– / UNAVAILABLE`, 전체 평가는 `PARTIAL`로 표시한다. 구간을 모르면 공식 총점을 만들지 않고 관측된 감점만 별도로 표시한다.
- 시나리오가 바뀌어도 수신/감점 코드를 수정할 필요는 없지만, 지도와 시나리오 메타데이터는 일치시켜야 한다. **VTD Play만으로 임의 시나리오의 공식 5구간·학교구역·종료선·신호 대응관계를 자동으로 알아내지는 못한다.**

## 2. 근거의 우선순위

1. 이번 메시지에 붙인 주최 측 답변 1~5: 기존 문서와 충돌하면 이 답변을 우선한다.
2. `HL 평가기준.docx`의 해당 평가 항목/채점 공통 기준: 수치, 차량 기준점, 점수.
3. 사용자가 정한 운영 조건: 제어로 차가 움직이면 평가 시작, VTD와 대시보드는 같은 PC, 제어기는 별도 PC, 신호 배너는 수신 불가 시 제외 가능.
4. 구현상 가정/임시 판정: 아래에 별도 표시. 주최 측 확정 기준이라고 부르지 않는다.

DOCX에는 확정 기준뿐 아니라 이전 제안/확인 필요 사항도 함께 있다. 특히 장애물 회피 시 중앙선 예외 제안은 이번 답변 3으로 폐기했다. 답변 1의 “유의미한 이탈”은 거리·시간 수치가 아니므로 문턱값을 채우지 않았다.

OBB 접촉은 평면 SAT 겹침과 높이 범위를 사용한 보수적 임시 판정이다. 실제 형상 접촉/물리 충돌 이벤트와 동일하지 않으며, 정확도 %를 검증 없이 제시할 수 없다. RDB `CONTACT_POINT`는 타이어/노면 접촉 정보이므로 차량 충돌 신호로 오용하지 않았다.

실선 차로변경은 현재 도로/차로 ID 전환을 변경 이벤트 시점으로 삼는다. OBB 기준의 **전체 차체가 차로를 완전히 옮긴 시점**과 다를 수 있다. 주최 측의 변경 완료 정의와 대조한 현장 검증이 필요하며, 이를 확정 정확도로 표시하지 않는다.

## 4. 공통 점수·세션 기준

- 경미 3점, 중대 6점. 같은 구간/항목이 3점에서 6점으로 격상되면 **추가 3점**, 합계 6점이다. 3+6=9로 계산하지 않는다.
- 속도 지속 위반은 시간에 비례해 반복 감점하지 않는다. 첫 위반 횟수/두 번째 위반으로 단계가 올라가는 차로 유지·실선 변경은 별도 항목 규칙을 유지한다.
- 리스폰은 첫 회 이후 매회 6점, 상한 없음. 중대위반 횟수에도 각각 반영한다.
- DOCX의 `도달 구간당 100점`을 채택했다. 음수 점수를 0으로 자르지 않는다. 영상의 초기 500점 표시는 모양 그대로 복사하지 않았다. **대회와 초기 500점 표시까지 같아야 한다면 총점 정책을 재확인해야 한다.**
- 실제 구간 좌표 없이 5등분하지 않는다. 어느 구간인지 모르는 샘플이 있으면 공식 총점은 `–`, 결과는 부분 평가다.
- 사용자의 “제어 후 차량이 움직이면 시작”을 구현상 속도 0.5km/h 이상이 0.5초 지속되는 조건으로 관측한다. **이 숫자는 노이즈 방지용 임시 기본값**이다. 제어기 명령 자체를 수신하는 것은 아니다.
- 종료는 DOCX의 후륜축 종료선 통과를 사용한다. 사용자가 앞서 말한 GOAL/마지막 체크포인트와 같은 위치가 되도록 실제 종료선을 설정해야 한다. 좌표가 없으면 완주를 자동 확정하지 않는다.
- 제한시간 기본 900초. 시뮬레이션 시간 기준이며 현실 시간과 다를 수 있다. 완료/시간초과 후 점수·거리·시간을 동결한다.
- 같은 시뮬레이션 시간의 반복 프레임(Pause)은 평가 시간을 누적하지 않는다. 끊긴 샘플 사이에 침범/정지 지속시간과 이동거리를 만들어 넣지 않는다. 시뮬레이션 시간이 전진한 수신 공백은 전체 주행시간에 포함된다.
- 시뮬레이션 시간/프레임이 뒤로 가면 Reset으로 새 세션을 준비한다. 이전 결과 파일은 보존한다. Reset을 리스폰 위반으로 계산하지 않는다.
- 앞차/보행자로 정당한 정지가 확인되면 녹색 미출발 타이머를 초기화한다. 이 타이머 초기화 방식과 통신 공백 처리는 구현 정책이며 추가 주최 측 확인 대상이다.

## 5. VTD PC에서 실행

대시보드는 **VTD 화면이 열린 Linux 데스크톱의 터미널에서** 실행한다. 제어기 PC에서 실행하는 명령이 아니다. 아래 경로는 해당 PC의 실제 저장소 경로로 바꾼다.

최초 준비(Ubuntu):

```bash
sudo apt update
sudo apt install python3-yaml ffmpeg x11-utils
cd /실제/HL_VTD
python3 tools/dashboard/check_environment.py
```

VTD를 Play한 상태에서 데이터 점검:

```bash
python3 tools/dashboard/check_environment.py --probe-rdb --rdb-host 127.0.0.1 --rdb-port 48190
```

대시보드 실행:

```bash
python3 tools/dashboard/server.py --host 127.0.0.1 --port 8765 --rdb-host 127.0.0.1 --rdb-port 48190 --video-source window
```

같은 PC 브라우저에서 `http://127.0.0.1:8765/` 접속. 포트 없는 `http://127.0.0.1/`는 다른 주소다. 서버는 계속 켜 둔다. 준비가 끝난 이후에는 VTD 상태 출력을 재연결하며 Play/차량 출발을 기다린다.

`48190`은 기본값이지 모든 VTD 설치의 보장된 포트가 아니다. VTD 설정에 RDB TCP 출력 서버가 있어야 하며 객체 상태/도로 위치/차로/차량 시스템/신호 패키지와 프레임 종료가 나와야 한다. 기존 제어기도 48190에 접속한다면 **동시 클라이언트 지원 여부를 확인하거나 평가기 전용 읽기 전용 출력 포트를 추가**하고 `--rdb-port`를 바꾼다. 평가기가 제어 포트를 가로채도록 구성하지 않는다.

### 영상

- `window`: 같은 X11 세션에서 `igVisualBroadcast`, `cam1`, `mainRS`, `birdRS` 등의 VTD 렌더링 창을 찾아 창 ID로 캡처한다. 브라우저 여러 개가 하나의 캡처 프로세스를 공유한다.
- 창 이동 후 재탐색이 가능하지만 축소/최소화/닫힘에 따라 스트림이 종료되므로 창을 열린 상태로 유지한다. FFmpeg의 `x11grab -window_id`를 지원하는 설치가 필요하다. [FFmpeg 공식 x11grab 문서](https://ffmpeg.org/ffmpeg-devices.html#x11grab)
- `--video-source rtsp --rtsp-url rtsp://127.0.0.1:8554/broadcast`도 지원한다. **VTD 쪽 RTSP 송출이 이미 구성되어 있을 때만** 사용할 수 있다. 이 옵션이 VTD 송출기를 새로 설치/설정하는 것은 아니다.
- `auto`는 우선 로컬 창을 찾고 없으면 설정된 RTSP를 사용한다. 로컬 캡처가 환경상 불가능하면 명시적으로 RTSP 모드를 선택한다.
- Wayland 네이티브 창, 잘못된 DISPLAY/Xauthority, SSH의 다른 화면 세션은 별도 해결이 필요하다. 이 경우 X11 세션에서 실행하거나 VTD RTSP를 사용한다.
- `/api/mainrs_status`의 `found:true`는 실제 최근 JPEG가 수신된 경우만 표시한다. 영상이 없을 때 `/api/mainrs_stream`의 503은 미송출 상태이며, 예전의 미구현 API 404와 다르다.
- 영상 없음과 채점 데이터 없음은 별개다. 한쪽만 연결되어도 다른 쪽의 정상 동작을 의미하지 않는다.
- `--host 0.0.0.0`은 다른 PC 접속이 필요할 때만 사용한다. 인증 없는 로컬 도구이므로 인터넷에 공개하지 않는다.

## 6. 설정해야 하는 데이터

기본 설정: `tools/dashboard/assessment_rules.yaml`. 변경 후 서버를 재시작한다. 다른 시나리오 설정 파일을 `--assessment-config 파일.yaml`로 지정할 수 있다.

| 설정 | 의미 |
|---|---|
| `map.xodr` | 실제 VTD가 로드한 XODR. 상대 경로는 저장소 기준. 현재 LivingLab 파일을 기본 사용 |
| `lane_keep.intrusion_m`, `duration_s` | 주최 측의 유의미한 이탈 수치. 아직 null |
| `metadata.ego_name` | 평가 대상 객체 이름. 기본 Ego. 시나리오에서 이름이 달라지면 맞춰야 함 |
| `metadata.scenario_id` | 기록용 시나리오 이름. 기본 VTD_LIVE |
| `metadata.sections` | `id`, `polygon: [[x,y], ...]`의 목록. 도로 전체를 공식 구간별로 빠짐없이, 겹치지 않게 구분 |
| `metadata.rear_axle_offset_m` | RDB 객체 기준점에서 뒤축까지 차량 전방 x축 방향의 부호 있는 거리. OBB 중심과 같다고 가정하면 안 됨 |
| `metadata.finish_line` | `begin`, `end`, `direction`으로 된 유한 종료선. direction=1은 begin→end의 왼쪽 법선 방향으로 통과, -1은 반대 |
| `metadata.school_zones` | `id`, `polygon`으로 된 실제 붉은 보호구역 영역 목록 |
| `metadata.crosswalks` | `id`, 볼록 `polygon`, 선택 `road_id`, `lane_ids`. 횡단 의도용 `crossing_roles`(객체 이름 목록), `entry_polygons`를 추가할 수 있음 |
| `metadata.stop_lines` | `id`, `begin`, `end`, `direction`, 정수 `signal_id`, `state_masks`, 선택 `road_id`, `lane_ids`. `state_masks`는 실제 RDB mask 값→RED/GREEN/YELLOW/FLASHING_RED 매핑 |
| `metadata.object_feed_complete` | 평가 범위 내 모든 필요한 객체가 RDB로 송출됨을 확인한 뒤 true. 기본 false. true라고 쓰는 것만으로 데이터 누락이 해결되지는 않음 |
| `metadata.object_roles` | 필요시 `객체이름: static_obstacle` 등의 명시적 분류. 정지 차량을 장애물로 바꾸지 않음 |
| `metadata.centerlines`, `sidewalk_boundaries` | XODR 대신 수동 보완할 경계. `id`, `begin`, `end`, `forbidden_side`(왼쪽 +1/오른쪽 -1), 선택 road/lane 필터 |
| `metadata.lane_boundaries` | 수동 실선 경계: `id`, `begin`, `end`, `type: solid`, 선택 road/lane 필터 |
| `session.respawn_jump_m` | 좌표 점프 임시 검출 문턱값. 기본 null. 정상 고속 이동/통신 끊김/Reset/실제 리스폰을 대조하고 설정 |

**키 누락과 빈 목록 `[]`은 다르다.** 누락은 모른다는 뜻이다. 빈 목록은 해당 지도/평가 범위에 그 요소가 없다고 확인했다는 뜻이다. 경고를 없애려고 임의로 `[]`를 넣지 않는다. 수동 중앙선/보도 경계 키가 있으면 XODR 자동 측정보다 우선하므로 빈 목록도 주의한다.

예를 들어 검증된 직선 종료선은 다음 구조다. 좌표 숫자는 설명용이며 실사용 좌표가 아니다.

```yaml
metadata:
  rear_axle_offset_m: -1.5  # 설명용: 반드시 실제 차량 기준점과 뒤축 위치로 교체
  finish_line:
    begin: [100.0, 5.0]    # 설명용: 실제 종료선으로 교체
    end: [100.0, -5.0]
    direction: 1          # 이 예시는 x<100 에서 x>=100 방향 통과
```

실제 설정은 이 예제만으로 충분하지 않다. 구간·학교구역·횡단보도·신호 매핑 등 위의 필요한 항목을 함께 채운다. 이미 저장소에 있는 학교구역 측정 점이나 기본 finish=(0,0)을 검증된 공식 영역/종료선으로 취급하지 않았다.

## 7. 기록·검증 결과

실행별 `output/assessment/<세션ID>.jsonl`에 설정 사본, 프레임별 측정, 관측 이벤트, 감점 변경, 종료 결과를 기록한다. 브라우저의 ‘결과 상세’에서도 최신 판정 근거와 미설정 항목을 확인한다. 전체 RDB 원본 녹화 파일은 아니며 관측/채점 증거 로그다. 현재 CSV 이력 선택기에 이 JSONL 세션을 재생하는 기능은 없다.

2026-09-08 개발 환경 검증:

- Linux 전체 Python 회귀 테스트 45개 통과(자동채점/수신/지도/영상 관련 26개 포함).
- 51/70, 31/35km/h 경계, 중앙선·보도 시간 경계, 정확히 2m 적색 정지, 녹색 5/10초, 점멸 정지, 횡단보도 3초 시험.
- 중복 감점 방지/격상, 리스폰 상한 예외·음수 점수, Reset·완주 동결, Pause/수신 공백 시험.
- 제공한 `viRDBIcd.h`에 대해 헤더/객체/도로/차로 구조체 크기·주요 오프셋을 C++ static_assert로 확인.
- 분할 TCP 패킷 수신, 잘못된 패킷 폐기, 평가기가 제어 데이터를 송신하지 않음을 테스트 서버로 확인.
- 실제 Chrome에서 15행, 점수·속도·중대횟수·리스폰 감점 갱신 확인, pageerror 없음. 점수 테스트는 명시적인 합성 API fixture로 수행했고 실제 VTD 주행 결과가 아님.
- 공유 JPEG 중계/연결 상태/프레임 노후화 단위 시험. 실제 X11 VTD 화면→FFmpeg→브라우저 경로는 미검증.
- 50Hz·15분에 해당하는 45,000행의 평가 1회 약 0.22초(개발 PC, 단순 합성 기록). VTD와 함께 실행할 때의 부하는 별도 측정 필요.

개발 WSL에서 사전 점검 결과 `ffmpeg`가 없었다. VTD PC에 설치되어 있다는 의미도, 없다는 의미도 아니다. **실제 VTD 설치 PC의 상태를 이 환경에서 대신 검증하지 않았다.**

재검증 명령:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tools/dashboard/check_environment.py --probe-rdb
```

## 8. 팀 인수 시험 체크리스트

1. VTD/웹 같은 PC에서 서버 실행. Play 전에는 대기, 출발 후에는 채점 중으로 전환되는지 확인.
2. RDB 완성 프레임, Ego, 속도, road/lane 정보가 실제로 들어오는지 확인. 제어기와 동시 접속해 주행 제어에 영향이 없는지 확인.
3. 실제 XODR와 메타데이터 일치 확인. 매 구간 경계·학교구역·횡단보도·정지선·종료선·후륜축 위치를 VTD 화면과 대조.
4. 각각 정상/경미/중대 사례를 별도로 실행하고 좌측 셀과 총점/중대 횟수 확인. 동일 구간 반복과 다음 구간 재발도 시험.
5. 차로 유지 임계값, 실선 변경 완료 시점, OBB 충돌과 실제 충돌의 차이, 보행자 의도/녹색 정지 사유, 임시 리스폰 검출을 주최 측 사례로 검증.
6. 참고 영상처럼 실제 VTD 영상이 오른쪽에 들어오는지 확인. 창 이동·재생 종료·재시작·최소화·복구 후 영상이 정지 화면을 LIVE로 표시하지 않는지 확인.
7. Pause 중 점수/주행시간 고정, 통신 끊김 경고, Resume 복구, Reset 후 이전 로그 보존/새 세션 생성 확인.
8. 실제 종료선 후륜축 통과로 완주 및 점수 동결, 900초 시간초과 종료, 리스폰 첫 회 면제/반복 감점 확인.

이 인수 시험 전에는 ‘대회 영상과 동일한 정확도로 15개 항목 자동채점 완료’라고 판단하지 않는다. 특히 신호 **배너**를 생략할 수 있다는 사용자 허용은 적색/녹색/점멸 **채점에 필요한 신호 데이터까지 생략해도 된다**는 뜻이 아니다.
# 최신 기준 안내

이 파일은 이전 구현의 참고 기록입니다. **현재 실행·채점 기준은 [최종 자동채점 기준](HL_VTD_자동채점_최종평가기준.md)을 사용하세요.** 아래 과거의 15항목, 이동 감지 시작, 도달 구간별 총점, 목표점 반경 설명은 현행 기준이 아닙니다.
