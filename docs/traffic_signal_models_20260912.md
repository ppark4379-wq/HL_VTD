# 주행 모델 선택

`config/control.yaml` 맨 위의 `model`로 선택한다. 현재 저장값은 **default**이다. YAML 변경 후 제어기를 다시 실행하면 적용된다.

```yaml
model: default
# default
# change_default
# traffic_light
# speed_default
# speed_traffic_light
```

- **default:** 커밋 `d42fd708b62cbb41fa5ff73039e66a7eb1d1433b` (`보도 밖 보행자 미리 감속`)의 주행 동작이다. 해당 커밋의 횡단보도 대기, 소형 정적 객체 보호, 복구 타이머 및 탐색 순번 초기화를 복원한다. 그 이후 M16 복구/횡단보도 정적 전환 변경과 신호 보완은 적용하지 않는다. 현재 YAML의 숫자 설정도 해당 커밋과 모두 동일하다.
- **change_default:** 이번 분리 요청 직전 `default`였던 현재 변경본이다. M16 정적 복구, 관측 위치 기반 정체 복구, 위험 시 탐색 순번 보존, 횡단 중 멈춘 객체의 0.75초 정적 회피 전환을 포함한다. 신호 보완과 속도 상향은 적용하지 않는다.
- **traffic_light:** 기존 동작 그대로 `change_default`에 신호 보완을 추가한다. 녹색(3 또는 5)을 받은 프레임에서 앞범퍼 중심점의 실제 이동 선분이 지도 정지선을 통과하면 해당 정지선의 통과 이력을 남긴다. 앞바퀴 기준이 아니다. 이후 같은 이미 통과한 정지선의 황색/적색으로 다시 정지하지 않는다. 같은 controller의 다음 정지선은 별도로 처리한다. 리스폰, 되돌아간 뒤 재접근, 모델 해제에서는 이전 통과 권한을 재사용하지 않는다.
- **speed_default / speed_traffic_light:** 사용자가 기존 동작 유지를 지정했다. 각각 **change_default / traffic_light**에 속도 설정만 추가한다. `speed_default`를 새 커밋 기준 default로 바꾸지 않았다. 현재 YAML의 저속 회피·진행 복구 목표 5km/h와 급커브 목표 6km/h를 10km/h로 올린다. 복구 내부 속도 가드도 목표와 함께 올리지만 직선 40, 일반 커브 30, 스쿨존 20, 차선 변경 15km/h 상한과 물리적 곡률 제한은 유지한다. 신호·긴급제동·안전 감속의 최종 명령을 10km/h로 강제하지 않는다. 다른 상한이 10km/h보다 낮으면 해당 상한을 우선한다.
- 모델은 설정 로드 시 한 번 적용하므로 20Hz 주행 루프에 탐색이나 반복 연산을 추가하지 않는다. 기본 모델로 재로드하면 스피드 모델의 덮어쓴 값이 남지 않는다. 이름이 없는 예전 YAML의 숫자 선택도 호환하지만, 이름이 있으면 이름을 우선한다. 잘못된 이름은 설정 오류로 거부한다.
- 녹색 통과를 관측하기 전에 황색/적색이면 정지선 접근과 제동을 유지한다. 신호 정지 목표를 횡단보도 입구로 옮기던 보정을 이 모델에서만 제외해 실제 신호 정지선을 사용한다. 목표는 앞범퍼 기준 1.5m이고 이 모델의 설정 여유는 0m 초과, 2m 미만만 허용한다.
- 신호 통과 이력은 신호 정지 요청만 제외한다. 보행자 횡단과 동적 위험 제동, 정적 회피 및 게이트웨이 복귀는 독립적으로 유지한다.

시작 로그의 `[model] default behavior=d42fd708` 또는 `[model] change_default behavior=working_changes`로 실제 선택을 확인한다. 모델은 주행 코드의 동작을 선택하며, 현재 사용자가 편집한 시나리오 XML/경로 파일을 과거 버전으로 되돌리지 않는다. M18 분석에서 `/tmp`로만 시험한 수정안은 어느 모델에도 새로 반영하지 않았다.

5개 모델 분리 검증: `hl_vtd` 빌드, 관련 CTest 12개 통과. 지정 커밋에서 직접 추출한 수정하지 않은 제어 테스트 소스도 현재 기본 동작에 연결해 7개 실행 모드를 통과했다. 신호 모델 선택/속도 값뿐 아니라, 기본 모델의 기존 횡단 대기·소형 정적 보호와 변경 모델의 정적 전환·복구 동작을 구분해 검사했다. 기본값으로 재로드 시 다른 모델의 옵션이 남지 않는 것도 검사한다. 로그는 `output/tmp/driving_models_d42fd70_20260912/`에 보관한다. 이 분리 이후 VTD 시나리오 재주행은 하지 않았다.

빌드 완료. 설정 검사 1개와 관련 주행 판단 검사 10개 통과. 두 모델의 동작 차이, 앞바퀴가 아직 정지선 전에 있을 때의 앞범퍼 통과, 통과 전 황색, 재시작/리스폰/모델 전환, 동일 controller의 다음 정지선, 경로 station 변경에 의한 잘못된 통과 방지, 횡단보도와 겹친 실제 정지선 위치를 검사했다.

생산 플래너와 제어기를 연결하고 속도 필터를 포함한 모의 주행에서, 약 10/20/30/50km/h의 적색·황색 접근 모두 정지선 앞범퍼 거리 1.4596~1.47276m에 정지했다. 이는 VTD 실제 재주행 완료 결과가 아니다. 로그는 `output/tmp/traffic_signal_models_20260912/`에 저장했다.
