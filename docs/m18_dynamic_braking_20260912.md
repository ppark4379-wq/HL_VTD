# M18 동적 차량 제동 분석 및 탈출 우선순위 복구 — 2026-09-12

## 기록에서 확인한 현상

분석 대상은 사용자의 최신 `output/verification/M18/m18_rviz/run.csv`이다. 아래 시각은 해당 파일의 **실행 경과 벽시계 시간**이다. 이번 작업에서는 VTD를 추가 실행하지 않았다.

첫 차량의 긴급제동이 아예 발생하지 않았다는 설명은 기록과 다르다. 제동 뒤의 진행 명령과 두 번째 차량에 대한 제동 유지 실패가 문제다. 수신 차량 6·7은 각각 약 8.33m/s로 기록돼 움직이는 차량으로 인식할 정보가 있었다.

이 실행은 `decision.log`와 `frames.jsonl`을 저장하지 않아 해당 순간의 내부 `raw_emergency`, `progress_recovery` 플래그 및 전체 예측 경로를 직접 확인할 수는 없다. 다만 −10에서 양의 가속으로 바뀌는 최종 명령, 5km/h 탈출 속도, 유지된 회피 표시와 아래 실제 코드의 우선순위가 일치한다. 이 동작을 일반 합성 장면의 전체 플래너·제어기 테스트에서도 검증했다.

## 원인

1. `applySimulationProgressRecovery`가 동적 위험을 계산하고도 이를 탈출 금지 조건으로 사용하지 않았다. 정지 타이머가 차면 위험이 지속되는 동안에도 활성화될 수 있었다.
2. 탈출 경로에서 동적 위험을 다시 검출해도 `persistent_risk_contact_authorized`를 기록하고 진행했다. 마지막에 `emergency=false`와 제동 유지 시간 0을 설정해 이미 발생한 제동 요청을 덮었다. 활성화 이후에는 새 차량이 접근해도 같은 우선순위가 적용됐다.
3. 첫 차량에는 정지 위치 문제도 있다. 실제 정지 자세를 고정하고 기록된 차량 6의 이동 OBB와 비교하면 14프레임 동안 겹친다. 즉 재출발을 막는 것만으로 첫 접촉까지 해결했다고 말할 수 없다. 이번 분석의 OBB 복원은 실제 로그의 접촉 28프레임과 일치하며 불일치는 0이다.

예측 설정은 5초/0.2초 간격이고 긴급제동 판단은 속도를 반영한 TTC 문턱을 별도로 사용한다. 예측 범위만 늘리는 것으로 제동을 덮는 우선순위 문제가 해결되지는 않는다. 정확한 초기 예측 시점 분석에는 저장되지 않은 전체 경로/관측 이력이 추가로 필요하다.

## 사용자 설명에 따라 적용한 변경

사용자 의도는 “위험이 남아 있어도 일정 시간 뒤 출발”이 아니라 “위험이 사라진 뒤에도 계속 멈춰 있는 상황 방지”이다.

- 기존 긴급제동 요청과 해제 유지 시간이 남아 있거나 동적 위험이 있으면 탈출을 취소하고 타이머를 초기화한다. 이미 진행 중인 탈출에도 동일하게 적용한다.
- 탈출 후보에서 움직이는 차량·보호 대상과의 접촉을 허용하던 선택 인자를 제거했다.
- 실제 출발할 탈출 경로를 다시 검사해 동적 위험이 있으면 제동을 유지한다. 위험 판정을 단순한 접촉 허용 표시로 바꾸지 않는다.
- 신호·보행자 정지 우선순위는 유지한다. 기존 OBB 예측 시간, TTC 문턱 및 제동 세기는 변경하지 않았다.
- 위험 해소 뒤의 일반 경로 복귀와, 정적 장애물·경로 실패·매칭 실패·잔류 제동 때문에 움직이지 못하는 경우의 기존 탈출은 유지한다.

이번 범위는 긴급제동 우선순위 복구다. 교차 차량의 통과 공간 앞에 별도 대기 위치를 확보하는 변경은 하지 않았다.

## 확인 결과

`hl_vtd`와 관련 도구 빌드 완료. 관련 CTest 9개 통과:

- 움직이는 차량 및 보호 대상이 시간 제한보다 오래 남아 있어도 제동 유지.
- 정적 장애물 탈출 중 새 동적 위험이 생기면 즉시 탈출 취소.
- 두 위험 차량 중 하나만 사라지면 대기 유지, 둘 다 사라지면 최종 제어 명령까지 재출발 확인.
- 정적 장애물 접촉 탈출, 후보/지도/참조 경로 소실, 신호 없는 게이트웨이 정체의 진행 유지.
- 신호 정지 정책, 기존 게이트웨이 처리, 소진 경로 복구 및 단계적 전역 탐색 회귀 검사 통과.
