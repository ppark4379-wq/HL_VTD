분석 후 사용자 승인에 따라 신호 접근 중 복구 경로 중단 조건을 수정했다. 분석 대상은 04:17경 시작한 `M18/m18_rviz` 실행이다. 이전 동적 차량 분석 실행과 run_id가 같아 원본 파일은 덮어써졌으며, 이번 구간은 `output/tmp/m18_distant_signal_stop_20260912/event_window.csv`에 별도로 보존했다.

- 303.650831초: (565.206604, −137.527893)에 거의 정지. 정지선 거리 47.749749m, 횡단보도 제어 활성은 0.

지도에서 controller 136에 연결된 정지선은 road 174의 590번, 좌표 (612.115, −116.186)이다. 정지 자세의 앞범퍼에서 이 좌표까지 직선 거리는 약 47.736m로 로그 거리와 일치한다. 따라서 정지선을 현재 위치로 잘못 투영한 현상으로 설명되지 않는다.

## 코드상 원인

1. `findActiveStopLine`은 최대 80m 앞까지 현재 controller와 연결된 정지선을 찾아 `updateStopRequests`에서 정지 계획을 만든다. 이 자체는 미리 감속할 목표를 설정하는 처리다.
2. `updateBehavior`의 정상 신호 속도는 남은 거리에서 위치 여유를 뺀 값에 정지 속도 프로파일을 적용한다. 약 48m 남은 상황에서 원래 5km/h라면 이 계산만으로 즉시 목표속도 0이 되지 않는다.
3. 하지만 `applySimulationProgressRecovery`는 **정지 계획이 존재한다는 `frame.stop.valid`만으로 복구용 경로 추종을 중단**한다. 정지선까지 접근 가능한 거리인지 검사하지 않는다.
4. 실제 로그도 황색 전환 순간 복구 진행 표시가 꺼지고 lookahead가 2m에서 3m로, target index가 12에서 4로, 조향이 0으로 바뀐다. 원래 추종 상태에서 목표속도 0이 남고, `runControlProcess`는 신호 정지 이유와 목표속도 0의 조합을 실제 정지 명령으로 받아 −10을 유지한다.
5. 적색 동안에는 같은 `stop.valid` 조건이 복구를 계속 막는다. 녹색 뒤에도 바로 출발하지 않고 복구 재활성화 후 5km/h로 돌아오는 기록이 이 경로와 일치한다.

이 실행에는 전체 frame history/decision trace가 없어 중단 직후 경로의 모든 샘플과 내부 분기 로그를 복원할 수는 없다. 정지선 거리, 신호 전환, 목표·가속 명령 및 추종 상태 전환은 run.csv에서 직접 확인했다. 짧은 원래 경로가 왜 남았는지까지 특정하려면 그 이전의 경로 생성 이력이 필요하다.

## 반영한 수정

- 적색·황색·적색점멸 정지 계획이 있어도 앞범퍼가 목표 정지 위치보다 멀면 복구 경로로 접근할 수 있다. 정상 경로가 사용 가능하면 기존 정상 추종이 우선한다.
- 복구 목표속도에도 정상 신호 정지와 같은 `sqrt(2 * comfortableDeceleration * (distance - trafficStopPositionMargin))` 상한을 적용한다. 설정된 정지 위치 여유는 앞범퍼 기준 1.5m다.
- 복구 경로의 누적 거리 원점이 달라도 정지선 거리는 원래 지도 기준 `sensedWorld.frontBumperPathS`로 계산한 값을 유지한다. `PlanningResult`에 신호 정지 이유와 거리를 남겨 최종 제어기의 거리 기반 제동도 계속 적용한다.
- 정지 위치 도달, 보행자 대기, 긴급제동은 복구 진행보다 우선한다. 신호 접근 중에도 기존 게이트웨이 대기 차량 간격 및 접근 경로 끝의 속도 상한을 유지한다.
- 정지 원인이 해제되면 기존 정상 경로 복귀·재출발 처리를 따른다. 특정 시나리오·신호 ID·차량 종류를 분기 조건으로 추가하지 않았다.

## 검증

`recovery_signal_approach`는 일반 경로가 없고 복구 경로만 사용 가능한 장면에서 녹색→적색/황색/적색점멸을 각각 검사한다. 수정 전에는 신호 전환 즉시 복구가 꺼지는 assertion으로 실패했다. 수정 후에는 planner와 최종 actuator를 0.05초 간격의 단순 종방향 적분 모델에 연결해 약 46m를 접근하고, 세 신호 모두 앞범퍼가 정지선 **1.43545m 앞**에서 정지했다. 적색 유지 중 정지, 녹색 재출발, 적색점멸 0.5초 정지 후 재출발도 검사한다.

복구 경로의 station 원점을 1000m 옮겨도 정지선 거리가 바뀌지 않는 조건을 포함했다. 기존 신호·보행자 시험에서도 시뮬레이션 복구 기능을 활성화했다. 게이트웨이 정지 대기와 동적 위험 지속·해제, 정상 경로 복귀, 확장 전역 탐색을 포함한 회귀 검사 **11개가 모두 통과**했다(6.83초). `hl_vtd` 빌드도 완료했으며 빌드·검사 로그는 위 증거 디렉터리에 보존했다.

이는 오프라인 회귀 검사이며 수정 후 VTD 실주행 결과는 아니다. 추가 계산은 기존에 계산한 대기 속도 상한 전달, 상수 개의 비교 및 복구 접근 시 제곱근 1회이며 새로운 경로 탐색 단계나 주기는 추가하지 않았다.
