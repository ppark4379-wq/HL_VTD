# 자동채점 정확도 감사 — 2026-09-10

## 결론

현재 구현을 14개 전 항목이 현장 검증된 완전 자동채점기라고 볼 수 없다.
수치 기준과 일부 기하 판정은 구현되어 있지만, 시나리오별 경로 연결 오류,
차로변경 방향 반전, 확정되지 않은 리스폰 검출, 신호 매핑 부재, 객체 송출
완전성 미확인이 있었다. 근거가 부족한 항목을 정상으로 간주해 500점에서
감점만 표시하면 실제보다 높은 점수를 만들 수 있으므로, 필수 입력이 하나라도
누락된 세션은 공식 점수를 표시하지 않는다.

## 이번 감사에서 수정한 공통 문제

- `run_scenario.py`가 현재 시나리오와 검증된 `route.csv`를 실행 프로필로
  게시하고, 대시보드가 첫 제어 패킷에서 이를 읽는다.
- 구간은 현재 경로의 시작 투영 S부터 마지막 S까지 누적 경로 길이로 정확히
  5등분한다. 경로 투영 누락 프레임과 각 구간 S 경계를 보고서에 남긴다.
- 화면 번호와 백엔드/로그 번호를 하나로 통일했다. 6=리스폰,
  7=방향지시등, 8=실선 변경, 9~11=신호, 13=정적 충돌,
  14=보행자 대응, 15=도로이용자 충돌이다.
- 구간 미설정 사건은 증거로 보존하되 공식 감점 합계에는 넣지 않는다.
- `UNAVAILABLE`, 경로/구간 누락, 보호구역 불확실, 측정 공백 또는 필수
  메타데이터 누락이 있으면 `official_score=null`로 보류한다.

## 남은 현장 승인 조건

다음 세 가지가 실제 VTD 셋업에서 확인되어야 `COMPLETE` 점수를 낼 수 있다.

1. 현재 시나리오 경로 투영이 전 구간에서 끊기지 않는지 확인한다.
2. 해당 경로의 정지선↔traffic controller ID와 RED/GREEN/YELLOW/FLASHING_RED
   상태값을 실제 RDB 로그로 확정한다.
3. 시나리오의 차량·보행자·정적 장애물 목록과 대시보드 Raw RDB 객체 목록을
   프레임별로 대조하여 `object_feed_complete`를 승인한다.

이 조건 전에는 화면에 숫자 공식 점수를 표시하지 않는 것이 오채점 방지 동작이다.
mainRS/birdRS는 판정 근거의 독립적인 사후 대조 자료이며, 영상만 보고 코드 판정을
소급 변경하지 않는다.
