# 전역 회피 실패 시 조기 로컬 회피

전역 경로 생성 알고리즘과 게이트웨이 목표는 변경하지 않는다. 실제 선택
경로 앞의 정적 장애물이 가까우면 별도 비동기 로컬 탐색을 시작한다.
전역 승인/실패 플래그와 무관하게 실제 장애물을 검사한다. 선택되지 않은
오래된 전역 경로의 장애물 때문에 안전한 현재 경로를 대체하지 않는다.
`stationary_path_blocked`가 발생할 때까지 기다리지 않는다.

## 동작

- 활성화 거리: 현재 설정 50m 또는 현재 속도 × 5초 중 큰 값. 탐색 범위에서
  안착 여유 12m를 뺀 거리로 제한한다.
- 최대 90m의 차선·차선 내 오프셋·허용된 점선 경계 상태를 연결하여
  연속 장애물 회피를 탐색한다. 차체 전체, 정적 객체, 노면, 실선,
  곡률 및 게이트웨이 도달 가능성을 검사한다.
- 새 로컬 경로를 만들 때 차선 중앙 상태만 연결한 완전한 경로를 먼저
  검사한다. 실패/시간 초과 시 기존 5개 횡방향 상태를 모두 사용한다.
  중앙 선호는 전역 비용이나 상시 재계획 트리거가 아니다. 중앙 후보에도
  동일한 차체·충돌·곡률·복귀/게이트웨이 검사가 적용된다.
- 새 결과는 현재 차량 위치에 다시 연결하고 최신 객체로 검증한 뒤에만
  원자적으로 채택한다. 오래된 미션/리스폰 결과는 사용하지 않는다.
- 안전한 로컬 경로는 유지한다. 남은 길이가 줄면 겹치는 다음 구간을
  준비한다. 새 탐색 대기/실패는 기존 로컬 플래너를 차단하지 않는다.
  채택한 로컬 경로가 정적/동적 장애물에 막혀도 기존 회피 탐색을 허용한다.
  연장 기준은 `max(20m, 현재 속도 × local_fallback_time_headway + 8m)`이다.
  장애물 조기 발견용 50m를 경로 연장 기준으로 재사용하지 않는다.
- 전역 경로 복귀는 실제 연결과 전방 경로 안전검사 후 수행한다.
  안전한 로컬 후반부를 먼저 버리거나 장애물과 겹치는 전역 경로로 즉시
  복귀하지 않는다. 회피 완료 후 남던 고정 저속 유지 플래그는 제거했다.
- 전역 기본 여유폭은 그대로다. 로컬 탐색만 기존 tight 여유폭을 대안으로
  사용한다. 0.05m 설정은 실제 추종 오차에 매우 민감하므로 통과 보장은 아니다.

## 설정: config/control.yaml의 planning

| 이름 | 현재 설정 | 의미 |
|---|---:|---|
| local_fallback_activation_distance | 50m | 로컬 탐색 조기 활성화 |
| local_fallback_time_headway | 5초 | 속도 비례 활성화 여유 |
| local_fallback_horizon | 90m | 로컬 탐색 범위 |
| local_fallback_retry_interval | 0.5초 | 같은 실패 장면 재시도 간격 |
| local_fallback_search_budget_ms | 80ms | 별도 worker 탐색 시간 예산 |
| local_fallback_speed_kph | 5km/h | 새 로컬 회피 실행/좁은 여유폭 경로 상한 |

worker는 하나만 실행하고 제어 스레드에서는 기다리지 않는다. 탐색 예산은
검사 지점 사이에서 확인하므로 엄밀한 실시간 실행 상한을 의미하지 않는다.
중앙 후보 탐색은 그래프 준비 후 남은 탐색 시간의 1/4, 최대 8ms를 사용하며,
동일 worker의 기존 시간 예산 안에서 수행한다. 전체 횡방향 탐색에 그래프와
개별 edge의 기하/충돌 검사 캐시를 재사용한다. 실패한 조합의 금지 목록은
초기화하여 중앙 후보 실패가 밀집 틈새의 부모 경로까지 막지 않게 한다.
전역 추종 기준 경로를 로컬 경로로 대체하던 0.5초 갱신 제한은 되돌렸다.
탐색 대기나 실패만으로 5km/h를 강제하지 않는다. 기존 속도 및 정지
판단은 유지하며 실제 로컬 회피/좁은 여유폭 경로에만 추가 상한을 적용한다.

## 확인 범위

신규 단위 테스트에서 조기 활성화, 빈 도로 비활성, 밀집 장애물 다단계
회피, 오래된 결과 거부, 실선 및 게이트웨이 도달성 조건을 확인했다.
설정 누락 시 기본값과 잘못된 설정 거부도 확인했다.
2026-09-10 중앙 후보 우선/경로 유지 변경 후 M17과 M09를 VTD에서 실행했다.
측정값·제한·M18 별도 분석은 `m17_stability_m18_corner_20260910.md`를 참고한다.
위의 일반 로컬 탐색 자체는 충돌 경로를 채택하지 않는다. 아래 VTD
진행 우선 모드가 활성화된 실행에서는 장시간 정체 후 별도 경로와
최종 명령으로 경로/확정 정적 장애물 정체를 우회한다. 동적 위험의
비상제동은 시간으로 해제하지 않는다. 신호·보행자·횡단보도
정지는 기존 해제 조건을 만족할 때까지 유지한다.

## VTD 진행 우선 복구 (2026-09-10)

현재 `config/control.yaml`은 사용자 요청에 따라
`planning.simulation_progress_recovery: 1`을 설정한다. 설정이 빠진
기존 구성과 C++ 기본 구성에서는 비활성(0)이다. 후진 명령은 추가하지 않았다.

| planning 파라미터 | 현재 설정 | 의미 |
|---|---:|---|
| simulation_progress_recovery | 1 | 0으로 바꾸면 충돌 감수 진행 비활성 |
| progress_recovery_stop_timeout | 3초 | 동적 위험 해소/정적 확정 이후 경로 정체 시 복구 진입 |
| progress_recovery_speed_kph | 3km/h | 복구 목표속도 상한 |
| progress_recovery_retry_interval | 0.5초 | 후보 실패/짧은 잔여 경로의 재탐색 간격 |
| progress_recovery_search_budget_ms | 15ms | 후보 사이에서 확인하는 탐색 예산 |

실측 저속 정체를 누적하며 0.5m 이동하면 정체 기준점을 갱신한다.
한 프레임 지연이나 Pause만으로 타이머가 만료되지 않도록 프레임별
누적 시간을 제한한다. 리스폰·미션 구간 변경·입력 이상·완주 시 복구를
초기화한다. 신호·보행자·횡단보도 정지 요청이 있으면 진행 우선 복구를
해제하고 정체 타이머도 초기화한다. 대기 시간을 복구 타이머로 누적하지
않으며, 기존 신호/횡단보도 해제 조건을 만족한 뒤에도 경로가 막힌
경우에만 새로 정체 시간을 센다. 지도와 현재 자세가 유효한 체크포인트
미션이 대상이다.

급정거·끼어들기 등 기존 동적 비상제동 계산은 유지한다. 동적 위험 또는
정적 전환 확인 중인 장애물이 정체 원인이면 복구 상태와 타이머를 초기화한다.
기존 `lane_change.stopped_dynamic_confirmation_time: 0.75`를 그대로 사용한다.
움직였던 객체가 속도·위치 변화 기준으로 정지 상태를 0.75초 유지하여
정적으로 확정된 뒤부터 복구 정체 3초를 새로 센다. 따라서 동적 위험으로
이미 기다린 시간을 정적 탈출 타이머에 합산하지 않는다. 처음부터 정적인
객체는 기존 판정대로 즉시 정적으로 분류한다.

현재 자세에서 6/8/10/12/16/20/24/30/40m 완료거리와 차선 내 오프셋을
조합한 C2 곡선 및 곡률을 점진적으로 바꾸는 짧은 전진 곡선을 생성한다.
이미 만들어진 경로도 현재 자세에 연결되는 잔여 부분만 후보로 평가한다.
차체의 실제 주행 노면·차선 경계·곡률 조건은 검사하지만, 확정 정적 객체 충돌은
탈락 조건 대신 겹침 깊이·접촉 거리·종점 부근 접촉의 비용으로 비교한다.
이미 겹친 객체도 제외하지 않으므로 접촉을 줄여 빠져나오는 경로가 선택될
수 있다. 동적/정적 미확정 객체와 보행자 크기 객체에 접촉하는 후보는
현재 위치와 단기 예측 위치를 검사하여 탈락시킨다.

선택한 경로는 별도 복구 상태에 유지하고 일반 안전 경로 캐시에 넣지 않는다.
움직이기 시작했다고 즉시 복구를 해제하지 않는다. 2m 이상 이동한 뒤
현재 자세에 연결되는 일반 무충돌 경로가 1초 유지될 때 인계한다.
선택 경로로도 3초간 0.5m 진행이 없으면 다른 초기 조향 후보를 탐색한다.
경로가 짧아지거나 충돌 외력으로 경로에서 벗어난 경우에도 다시 생성한다.
보관한 복구 경로도 매 프레임 실제 명령 직전에 동적 위험을 검사한다.
정적이었던 장애물이 다시 움직이거나 새 동적 위험이 생기면 복구를 취소하고
비상제동을 적용한다. 일반 경로의 위험 검사와 별도로 실제 복구 경로도 검사한다.

복구 명령은 기존 속도 제한/비상제동 판단 뒤에서 적용한다. 따라서 같은
정적 충돌 판정이 매 프레임 목표속도를 다시 0으로 만드는 순환을 끊고,
정적 복구에 한해 비상제동의 조향 고정도 해제한다. 동적 위험이 있으면
이 우회를 적용하지 않는다. 충돌 검사 결과와 감점 로그는 지우지 않는다.
RViz에는 주황색 `RECOVERY: contact_allowed`와 실제 복구 경로를 표시하고,
`latest.json`에는 무시한 정지 이유·비상제동·접촉 예상을 별도 기록한다.

통신/입력 이상, 완주 정지, 유효한 주행 기하를 전혀 만들 수 없는 상황은
양의 속도로 덮어쓰지 않는다. 가속 명령을 보내도 시뮬레이터의 물리적
접촉 때문에 실제로 이동하지 못할 수 있다. 이 모드는 충돌 감점을
감수하는 VTD 실험 설정이며 실차용이 아니다. 신호/횡단보도 대기의
시간 제한이나 강제 해제 기능은 없다.

이번 복구 기능의 주행/회귀 검증은 사용자 요청에 따라 실행하지 않는다.

### 복구 계산의 중복 제거

정적 판정·동적 위험·복구 타이머·후보 순서·비용식·검사 주기는 유지한다.
같은 탐색에서 객체의 정적/보호 대상 여부와 속도 성분을 한 번 계산하고,
예측 시간이 상한에 도달한 이후에는 동일한 예측 OBB를 재사용한다.
축 정렬 경계가 확실히 떨어진 두 OBB는 정밀 SAT 계산을 생략하지만,
경계가 닿거나 매우 가까운 경우에는 기존 SAT 계산을 그대로 수행한다.
캐시는 해당 함수 호출 안에서만 유지하며 다음 프레임에는 다시 만든다.

복구 인계 판단은 필요한 Ego 경로 좌표만 투영한다. 인계 조건이 이미
불충족이면 해당 투영도 하지 않는다. 새 경로 채택 시 동일 경로를 두 번
투영하던 부분과 실제 명령 경로를 두 번 생성하던 부분을 제거하고,
이미 만들어진 경로/WorldState의 소유권을 이동해 중복 복사를 줄인다.
보호할 동적 객체가 없는 프레임에는 객체 전체를 복사했다가 모두 지우는
작업도 하지 않는다. 실제 주행의 처리 시간/제어 주파수는 미계측이다.
벽시계 기준 탐색 예산은 그대로이므로 빨라진 만큼 한 호출에서 검사하는
후보 수와 예산 경계에서 선택되는 경로는 달라질 수 있다.

### M17 진단 이후: 단계별 복귀 탐색 및 접촉 경로 갱신

앞 절은 당시 최적화 기록이다. 이후 사용자 요청으로 아래 동작을 변경했다.

- 일반 코리더 로컬 탐색(tier 0)이 실패하면, 다음 탐색에서는 기존에 증명된
  현재 출구/다음 도로 범위와 더 긴 안착 구간을 사용한다(tier 1).
  로컬 전방 탐색 길이는 기존 값에 30m를 더하되 최대 120m다.
- 그것도 실패하면 주변의 같은 진행 방향 주행면을 제한적으로 사용한다(tier 2).
  추가 차선 중심 샘플은 정식 차선 중심 샘플에서 4m 이내, 방향 차이는 0.35rad
  이내여야 한다. 고도 정보를 얻을 수 있으면 높이 차이 1m 이하를 확인한다.
  경로 중심이 기존 허용 주행면 밖에 있는 누적 길이는 최대 40m다.
  이는 코리더 경계에서 무조건 4m까지 허용한다는 의미가 아니다.
- 일반 전역 그래프/게이트웨이 비용/미션 목표는 변경하지 않는다. 별도의
  후보 전용 주행면 마스크와 겹치는 연결 도로 사이의 복귀 곡선을 사용한다.
  실선·차체 전체 주행면·곡률·정적/동적 충돌 검사는 유지한다.
  복귀 연결은 코리더 밖 출발뿐 아니라, 아직 정식 차선 안에 있지만
  게이트웨이까지 횡방향 정렬이 필요한 지점에서도 미리 생성한다.
- 복귀 차선은 게이트웨이에 도달 가능한 정식 차선이어야 한다. 목표 단면을
  건너가는 경로는 그 단면을 실제 선택 차선에서 지나야 한다.
  게이트웨이를 옆으로 건너뛴 다음 목표 뒤에 합류하는 후보는 거절한다.
  후보 생성 자체로 미션 진행/완주 상태를 바꾸지는 않는다.
- 확장 탐색은 복귀 노드를 고른 뒤 8m 이상의 안착 꼬리를 생성·검사한다.
  점/오프셋만 있는 A* 상태에서 ‘부모 경로에 이미 8m 안착이 있어야 함’을
  요구하면 최저 비용 부모가 복귀를 계속 뒤로 미뤄 유효 경로를 놓칠 수 있었다.
- 일반 로컬 worker 예산은 80ms, 확장 복귀 worker 예산은
  `planning.local_reentry_search_budget_ms=240`이다. 둘 다 비동기이며
  제어 스레드는 완료를 기다리지 않는다. 결과는 현재 자세와 관측으로 다시 검사한다.
  탐색 실패에는 시간 예산 소진도 포함되므로 모든 가능한 경로의 부재를 뜻하지 않는다.
- 기존 경로가 이탈/소진돼 장애물 거리를 구하지 못하면, 실제 도로의 짧은
  진행 경로를 ‘탐색을 켤지’ 판단하는 데만 사용한다. 그것을 그대로 추종하지 않는다.

VTD 접촉 복구는 좌우/정면 후보를 교차 배치하고 세 후보 단위로 시간 예산을
확인한다. 15ms는 후보 묶음과 현재 경로 재평가 비용 때문에 초과할 수 있는
연성 예산이다. 발견한 무접촉 후보가 접촉 후보보다 항상 우선한다.
접촉 후보 사이에는 최종 겹침 여부, 겹침 깊이/적분/거리와 마지막 접촉까지의
거리를 비교한다. 실제 VTD 감점을 계산하거나 전역 최적성을 보장하지는 않는다.

현재 경로도 매 탐색에서 최신 관측으로 재평가한다. 같은 등급의 후보는 비용이
5% 이상 좋아질 때 바꿔 작은 점수 차이로 좌우가 흔들리지 않게 한다.
접촉 예상/실제 접촉이면 움직이고 있어도 0.5초 간격으로 탐색을 이어간다.
현재 경로를 그대로 재확인한 것은 ‘새 탈출 시도’로 세지 않아 정체 타이머를
초기화하지 않는다. 검증된 무접촉 일반 경로가 준비되면 접촉 복구에서 우선 인계한다.

신호·횡단보도 요청은 복구 명령을 계속 막는다. 다만 별도로 존재하는 정적
경로 막힘 이력을 보존해 녹색 신호마다 3초를 다시 기다리는 중복 대기를 없앴다.
신호 대기만으로 복구가 켜지지는 않으며, 동적 위험/미확정 정지 객체는 여전히
복구 이력과 경로를 초기화한다. 대기 중 저장 경로를 무검사로 실행하지 않는다.

집중 회귀 테스트: `progress_recovery_selection`, `bounded_corridor_reentry`.
후자는 긴 차량 회피 후 정식 차선 복귀, 탐색 단계 순서, 전역 권한 불변,
목표 단면 건너뛰기 거절을 확인한다. M17 실제 완주 보장은 별도 주행 검증 사항이다.
