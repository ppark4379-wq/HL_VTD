# 게이트웨이 차선 면 누락 수정

검토 SVG를 만드는 오프라인 생성기의 수정이다. 정지선이나 횡단보도를 기준으로 자르는 로직은 없었다. 진입과 진출을 모두 연결하는 차선만 게이트웨이에 남기면서, 한쪽 끝에서 폭이 0이 되는 합류·확장 차선이 빠졌다.

`whole_mission_corridors.py`는 경로 연결용 `connection_lanes`와 면 표현용 `surface_lanes`를 구분한다. 동일 road/section/방향의 차선 중 한쪽 폭이 0이고, 다른 쪽이 현재 진입·진출 콜리더에 연결되며, 이미 포함된 차선과 전체 구간의 경계를 공유하는 차선을 추가한다. 허용 경계 오차는 0.1 m다. 추가한 근거와 경계 오차는 `surface_extensions`에 저장하고, 진입·진출 단면도 함께 확장한다. 곡선과 폭 변화는 원래 XODR 샘플을 사용한다.

경로 탐색 그래프와 양방향으로 통과 가능한 차선 집합은 유지한다. 추가 면의 도로 접속부도 기존 면 단절 검사에 포함한다. 반대 방향, 다른 연결 도로, 경계가 떨어진 차선, 폭이 줄지 않는 막다른 차선은 추가하지 않는다. 지도에서 driving으로 내보내지 않은 none/border/sidewalk 면은 대상이 아니다.

| 확인 구간 | 처리 |
| --- | --- |
| A05 / R2399 | 합류 차선 -2 추가 |
| A06 / R3099 | 합류 차선 -2 추가 |
| A06 / R3093 | 합류 차선 -1 추가 |
| A12 / R1973 | 확장 차선 -3, -2 추가 |
| A18 / R1824 | 합류 차선 -2 추가 |
| A02 / R3145 | 기존 두 차선 유지. 옆 R3024는 R3018로 연결되고, 선택된 진출 콜리더는 R3142다. 별도 도로 분기를 합치지 않았다. |

A02에서도 다른 게이트웨이 R2765의 합류 차선 -6은 이 수정으로 복원되었다.

현재 저장된 45개 경로의 체크포인트 CSV와 선택 경로를 유지하며 SVG/PNG 및 JSON을 재생성했다. 총 30개 차선 면이 추가되었고, 222개 게이트웨이의 기존 연결 검증과 추가 면의 접속부 검사를 통과했다. 면 단절은 0개다. 단위·회귀 테스트 15개가 통과했다.

재생성 명령(PowerShell):

```powershell
& output/verification/gateway_diagnostics_env/Scripts/python.exe -X utf8 tools/verification/rebuild_random_corridors.py --geometry output/콜리더_게이트웨이 --output output/콜리더_게이트웨이/자동생성_20개 --review A02:3145 --review A05:2399 --review A06:3099 --review A06:3093 --review A12:1973 --review A18:1824
```

`gateway_surface_review/index.html`에 수정 전후 확대 비교가 있고, `surface_rebuild.json`에 경로별 추가 차선과 입력·소스 해시가 있다. 재생성 도구는 기존 체크포인트를 사용하며, 저장된 선택 경로가 바뀌면 해당 경로의 결과를 덮어쓰기 전에 중단한다. 기존 중심선 단차 항목과 차량 런타임 적용 여부는 별도 검증 항목으로 유지한다.
