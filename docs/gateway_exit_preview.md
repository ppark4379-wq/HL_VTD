# 게이트웨이 → 다음 콜리더 전역 회피 연결

## 확인한 M11 상태

사용자 실행 `output/verification/M11/m11_rviz`에서 연결도로 `3027:-3`의 트럭 11 앞 정지가 확인됐다. 경로는 남아 있고 긴급제동은 아니었다. 전역 재탐색은 실패 상태였으며 안전속도 검사가 앞 장애물을 검출했다. 전체 판단로그가 저장되지 않아 이번 실행의 개별 후보 탈락 이유까지 확정하지는 못했다.

종전 전역 탐색은 보통 진출도로 진입 약 2m의 목표를 만나면 종료했다. 다음 콜리더 연결 비용은 존재했지만 장애물을 반영하지 않았다. M11의 같은 출구 차선 `3027:-2 → 2806:-3`와 사전 분기 T194도 존재하나 미션 허용 차선에서 누락됐다.

## 공통 코드 변경

- 비최종 출구 목표는 특정 차선 중심이 아니라 허용된 동일 출구도로·동방향 차선에서의 진출 단면 통과로 인정한다. 최종 도착 조건은 유지한다.
- 같은 연결도로에서 실제 종방향 successor로 지정 출구 및 다음 미션 구간에 연결되는 추가 차선만 허용한다. 다른 회전도로나 교차로 전체를 열지 않는다.
- 전역 탐색은 실제 출구 단면에서 종방향 연결을 따라 다음 일반도로 콜리더 안쪽까지 이어진다. 기본 거리는 `max(lattice_short_distance, lattice_medium_distance, lattice_long_distance)`인 30m다. 가까운 다음 교차로 앞 또는 최종 도착점에서 제한한다. road ID 경계만으로 길이를 자르지 않는다.
- 새 목표까지 도달한 결과라도 실제 현재 게이트웨이 통과가 확인되지 않으면 승인하지 않는다. 예상 경로 생성으로 미션 순서를 미리 진행시키지 않는다.
- 실제 진출 후 다음 구간으로 바뀌면 미리 만든 겹치는 경로의 남은 부분을 새 허용 면·현재 차체 자세·최신 장애물로 다시 검사한다. 통과한 부분만 유지하며 다음 게이트웨이까지의 새 전역 탐색을 비동기로 진행한다.
- 차체 크기, 정적 장애물 여유, 차선 규칙, 신호등·보행자·긴급제동 규칙은 완화하지 않았다.

진단에는 `exit_preview=1`, `includes_exit_preview`, `exit_preview_handoff_retained/rejected`를 표시한다. M11/M14 번호에 따른 탐색 분기는 없다.

## 확인 범위

이번 작업은 기존 로그와 코드 분석 및 코드 수정·빌드까지만 수행했다. 사용자 요청에 따라 새 VTD 주행, 리플레이 및 테스트 실행은 하지 않았다. M11/M14 실제 통과 성공이나 모든 경우의 회피 성공을 주장하지 않는다.

## 후속: 생성된 회피 경로의 정적 정지 오판

M11의 `stationary_path_blocked` 기록(2806:-4, x1459.8712/y489.9815)은 EBS가 아니라 선택 경로의 정적 속도 상한이었다. 전역 경로 승인에는 차체+0.30m를 썼지만, 속도 판정은 미래 회피곡선과 주차차량의 방향 차이가 35도를 넘으면 1.50m를 더해 같은 경로를 막았다. 저장된 경로를 이용한 기하 분석에서도 0.30m 여유로는 겹치지 않고 추가 1.50m에서만 겹치는 현상이 확인됐다(저장 경로는 간소화돼 원본 거리와 차이는 있음).

`corridorStationaryFreeDistance`의 선택 경로 속도 검사에서만 이 추가 여유를 사용하지 않도록 변경했다. 승인된 경로와 같은 차체·요청 여유·노면 판정을 사용하며 실제 현재 충돌 및 실제 막힌 경로의 속도 상한은 유지한다. 전역/로컬 경로 생성, 다른 교차차량 판단, 동적 예측, 긴급제동, 신호·보행자 로직은 변경하지 않았다. 회귀검사 코드는 추가했으나 사용자 요청에 따라 실행하지 않았다.
