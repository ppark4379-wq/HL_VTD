# 게이트웨이 진입 차선 대기 수정 검증

## 수정 범위와 원인

- `laneGraph`는 종방향 도로 연결뿐 아니라 합법적인 차선변경 연결도 포함한다. 기존 대기 차선 역탐색이 둘을 구분하지 않아, 추가 차선변경이 필요한 옆 차선도 게이트웨이 진입 차선으로 인정했다.
- 장애물을 제외하고 구한 전체 경로를 첫 장애물 앞에서 자르는 방식은 차선변경을 완료하기 전에 대기점을 만들 수 있었다.
- 이제 선언된 게이트웨이의 종방향 선행 차선에서 대기열 뒤의 목표점을 먼저 찾는다. 실제 장애물을 모두 유지한 검색으로 그 목표점까지의 경로를 검증한다. 차선 중앙 후보를 먼저, 없으면 기존 횡방향 샘플을 사용한다.
- 완전한 무충돌 게이트웨이 경로가 최우선이다. 다음이 진입 차선 대기열 뒤로의 무충돌 접근이다. 해당 접근 경로도 없을 때만 기존 부분 접근을 허용한다. 부분 접근은 게이트웨이 통과 판정으로 사용하지 않는다.
- 초록/초록+좌회전 신호에서 정적 정체가 지속되면 기존 `progress_recovery_stop_timeout: 3.0`초 후 시뮬레이션 복구 탐색을 허용한다. 신호·횡단보도 정지와 동적 위험 판정은 복구에 앞선다. 미완주가 절대 없다는 보장은 아니다.
- 시나리오 번호, 차량 ID, 특정 좌표 조건을 추가하지 않았다. 이번 진입 차선 수정에서는 주행 속도값, NPC, VTD 설정, 시나리오 파일을 변경하지 않았다. 기존 사용자 설정의 회피 여유 0.50m와 복구 속도 5km/h는 유지했다.

## 자동 테스트

- 단일 막힌 게이트웨이 진입 차선 우선, 복수 게이트웨이 대기, 한쪽 게이트웨이 개방 시 무충돌 전체 경로 우선, 횡단보도 ID 이탈/재관측, 경로 인계·복귀·밀집 검색 관련 테스트 통과.
- 합법적인 횡이동 링크와 더 가까운 옆 차선 장애물을 함께 넣은 합성 테스트에서, 도달 가능한 실제 게이트웨이 차선 뒤를 우선 선택함을 확인했다.
- 확대 실행한 37개 테스트 중 34개 통과, 3개 실패. 실패한 `mission_exit_target_tests`, `controller_logic_tests::testCloseMovingLeadMayCommandStop`, `corridor_m08_gateway_replay`는 수정 전 HEAD `684b105`의 별도 빌드에서도 동일 실패를 확인했다. 이 작업에서 그 별도 문제를 숨기거나 테스트 기대값을 바꾸지 않았다.
- 이전에 기준 버전에서 실패를 확인한 별도 리플레이 일부는 확대 실행에서 제외했다. 따라서 전체 테스트/전체 시나리오가 모두 정상이라는 결론은 내리지 않는다.
